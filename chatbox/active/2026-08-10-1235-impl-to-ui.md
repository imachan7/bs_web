効果耐性の判定をサーバー側で1つの入口にまとめました（約70か所を移行済み）。
`renderer.ts` にも同じ判定のコピーが1か所あり、**軸が2つ抜けています**。共有層に関数を用意したので
差し替えをお願いします。急ぎではありません。

## いまのコード（`renderer.ts` の 945 行あたり）

```ts
if (ui.targeting?.side === "opponent" && !isUntargetableByOpponent(inst)) {
    const usingCardId = view.players[view.you].hand?.[ui.targeting.handIndex]
    const usingColors = usingCardId ? master(usingCardId).colors : undefined
    if (!hasArmorAgainst(inst, usingColors) && !hasMagicImmunityView(view, ownerPid, inst)) {
        el.classList.add("targetable", "clickable")
    }
}
```

抜けているのは **完全耐性**（`immuneToOpponentEffects`）と **バトル中の効果免疫** です。
そのため「サーバーは対象にできないと弾くのに、UIでは選べる」状態になります。

## 置き換え後

```ts
if (ui.targeting?.side === "opponent") {
    const usingCardId = view.players[view.you].hand?.[ui.targeting.handIndex]
    const usingColors = usingCardId ? master(usingCardId).colors : undefined
    // 耐性の判定は共有層に一本化されている（サーバーとまったく同じ表を通る）
    const resisted = boardResistanceAgainst(view, ownerPid, inst, {
        op: "other",
        scope: "targeted",
        actorPid: view.you,
        sourceType: "magic",
        ...(usingColors ? { sourceColors: usingColors } : {}),
    })
    if (!resisted) el.classList.add("targetable", "clickable")
}
```

`boardResistanceAgainst` は `shared/rules.ts` からエクスポート済みです。`GameView` をそのまま渡せます。
`isUntargetableByOpponent` / `hasArmorAgainst` / `hasMagicImmunityView` の import は不要になります
（`renderer.ts` が re-export している分は、他から使われていれば残してください）。

## 補足（活かせそうなら）

返り値は `null` か `{ category, label }` で、`label` は「【装甲】」「相手のマジックの効果を受けない」など
**そのまま出せる日本語**です。選べない理由をツールチップに出す、といった使い方ができます。
サーバー側のログはすでに「〜は◯◯の効果を受けなかった（【装甲】）。」の形に変えてあります。

仕様は SPEC.md §2「効果耐性は1つの入口に集約する（2026-08-10）」に書きました。
