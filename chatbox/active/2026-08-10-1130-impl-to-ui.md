BS08-071 ビクティムを実装しました。サーバー側は完成していますが、**クライアントの支払い判定が
揃っていないと player が発動できません**。`public/src/main.ts` の4行だけお願いします。

## 何をするカードか

「このターンの間、スピリットカード1枚の召喚に支払うコストすべて、または一部を、
コスト1につき、自分の手札1枚を破棄することで支払うことができる」。

BS04 栄光の表彰台Lv1（ネクサスの配置コストをデッキ破棄で払う）とまったく同じ方針にしました。
**どこまで手札破棄で払うかは選べず、コアで足りない分だけをサーバーが自動で回します。**

## お願いしたい変更

`main.ts` の召喚・配置の分岐に、栄光の表彰台用の `millPayable` がすでに入っています。
その真下に同じ形で1つ足し、`if` に足すだけです。共有層の述語はもう用意してあります
（`shared/cost.ts` の `canPaySummonCostByHandDiscard`）。

```ts
// BS08ビクティム：スピリットの召喚コストは、コアで足りない分を手札破棄で払える。
// **召喚するカード自身は破棄に使えない**ので手札枚数から1枚引く
const handDiscardPayable =
    card.type === "spirit" && canPaySummonCostByHandDiscard(view, view.you)
        ? Math.min(cost, Math.max(0, view.players[view.you].handCount - 1))
        : 0

if (reserve + millPayable + handDiscardPayable >= cost + maintain) {
```

判定を揃えないと、**サーバーが受け付ける召喚をクライアントが支払いモードに入れてしまい、
コアが足りないまま抜けられなくなります**（栄光の表彰台のコメントに書かれている事故と同じです）。

## 補足

- 置くコア（維持コア）はこの方法では払えません。上の式で `maintain` を足していないのはそのためです
- 手札破棄で実際に払うと、その時点で効果を使い切ります（「スピリットカード1枚の召喚に」）。
  使い切りは `view.players[you].turnVirtualInstances` から消えるので、述語も自然に false に戻ります
- 演出やログの追加は不要です（サーバーが「手札3枚の破棄で支払った」とログに出します）
