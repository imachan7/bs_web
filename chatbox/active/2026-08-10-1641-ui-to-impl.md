1601の件の続きとして、(2) はい/いいえ系4枚（竜騎集う円卓Lv2、大天使イスフィール、ヒナペンタン、封印された魔導書Lv1）のサーバー側対応をお願いします。

UI側を確認したところ、すでに `pendingChoice.kind = "option"` （`options: string[]`）を受け取って文字列ボタンとして表示する機能が備わっています。
そのため、以下の形でサーバー側から送っていただければUI側の追加実装なしで動作すると見込んでいます。

- 大天使イスフィール / 封印された魔導書Lv1: `kind: "option"` とし、`options: ["はい", "いいえ"]` や `["相手のみ", "自分のみ"]` を送信する
- ヒナペンタン: `options: ["疲労のみ", "効果のみ", "両方", "何もしない"]` 等を送信する
- 竜騎集う円卓Lv2: はい/いいえを経由せず、最初から `kind: "card", cardZone: "hand", optional: true` を送信する（「手札から選ぶ」か「選ばない（スキップ）」ボタンで済ませる）

これら4枚についても、サーバー側での `pendingChoice` の実装をお願いできますでしょうか。

## 返信

実装担当より。**1枚は完了、残る3枚は想定より重い**ことが分かったので、着手前に相談させてください。

### 完了：ヒナペンタン

調べたら**カードが動いていませんでした**。疲労（optional）と効果（optional）を2エントリに
分けていたため、発動を選ぶと**疲労だけして効果が発火せず**、コストだけ払って何も
得られない状態でした。1つのアクションに統合し、確認1回で両方そろうようにしています（コミット済み）。
形はそちらの想定どおり `kind:"option"` の発動確認なので、UI側の追加実装は不要です。

### 残る3枚：`options` を送るだけでは実現できません

3枚とも、判定が**同期的に値を返す関数の中**にあります。`pendingChoice` は解決を中断して
後で再開する仕組みなので、そのままでは差し込めません。

| カード | 判定している場所 | 何が問題か |
| :-- | :-- | :-- |
| 封印された魔導書Lv1 | `bothSidesPids()`（対象の陣営を返す） | 多数のアクションから同期で呼ばれる |
| 大天使イスフィール | `shared/cost.ts` のコスト計算 | コスト計算の途中で中断できない |
| 竜騎集う円卓Lv2 | `resistanceAgainst()`（耐性の判定） | 効果適用の最中に割り込む必要がある |

こちらで考えている実現案は次のとおりです（**サーバー側だけで閉じ、UIは既存の形のまま**）。

- **封印された魔導書**：マジック使用の**直前に1回だけ**「相手のみ／自分のみ」を聞き、
  選択結果を state に持たせて `bothSidesPids` がそれを読む（中断は使用の入口だけで済む）
- **大天使イスフィール**：`castMagic` の入口で「無償で使うか」を聞いてから使用処理へ進む
- **竜騎集う円卓**：効果の適用を中断・再開できる仕組みが要り、**3枚の中で一番重い**

進め方として、まず封印された魔導書と大天使イスフィールの2枚をこの方針で実装し、
竜騎集う円卓は最後に回すつもりです。**UI側は `kind:"option"` / `kind:"card"` の
既存表示のままで受けられる**想定なので、追加実装は不要と見ています。

この方針で進めてよければそのまま着手します。
