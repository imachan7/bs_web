# chatbox — エージェント間連絡の運用ルール

実装担当（Claude）・設計担当（Claude）・UI担当（Gemini）の連絡帳。
**このファイルと [INDEX.md](./INDEX.md) 以外は、必要になるまで読まない。**

## なぜこの形なのか

以前は `chatbox.md` 1ファイルへの追記式だった。86件・260KB まで肥大化し、
**エージェントが起動のたびに全履歴を読むだけで7〜8万トークンを消費していた**。
過去ログを読まないと現在の仕様が分からない状態だったため、全読みが正当化されてしまっていた。
そこで (1) 1メッセージ1ファイルに分割し、(2) 確定した判断を `../DECISIONS.md` へ追い出した。

副次的な効果として、`bs_web` / `bs_web-ui` の2クローン間で `chatbox.md` が衝突する問題も解消した。

## 構成

| 場所 | 中身 |
| :-- | :-- |
| `INDEX.md` | やりとり中の一覧。**常時読むのはこれだけ**。`active/` からの自動生成物 |
| `active/` | 未処理・進行中のメッセージ（1件1ファイル） |
| `archive/YYYY-MM.md` | 完了した過去ログ。**丸読み禁止** |
| `../DECISIONS.md` | 確定した判断の台帳。1件1〜3行 |

## 5つのルール

1. **`archive/` を無条件に読まない。** 必要なときは `grep` で当たりを付け、
   `Read` の offset/limit で該当箇所だけ読む。`archive/2026-07.md` だけで7万トークンある
2. **起動時に読むのは `INDEX.md` と自分宛の未処理メッセージだけ。**
   `npx tsx scripts/chatbox.ts inbox <役割>` が自分宛の未処理をパス付きで出す
3. **1メッセージは 4KB / 60行以内。** 長い設計・調査結果は別ドキュメント（`SPEC.md`・`*.md`）に書いて、
   ここからは参照リンクを張る
4. **`done` にするとき、残すべき結論を `../DECISIONS.md` へ1〜3行で転記する。**
   これを飛ばすと「過去ログを読まないと分からない」状態に戻る。
   仕様として確定したものは `SPEC.md` に書き、DECISIONS.md からは消してよい
5. **作業報告・コミット連絡を長文で書かない。** コミットメッセージと `git log` で足りる

## コマンド

```
npx tsx scripts/chatbox.ts inbox 実装担当                       自分宛の未処理を一覧
npx tsx scripts/chatbox.ts new --from 実装担当 --to UI担当 --title "件名"
npx tsx scripts/chatbox.ts done 2026-07-31-1500                完了にしてアーカイブへ
npx tsx scripts/chatbox.ts index                               INDEX.md を再生成
```

役割は `実装担当` / `設計担当` / `UI担当`（`impl` / `design` / `ui` でも通る）。
状態は `依頼中` / `作業中` / `完了`。

`INDEX.md` は生成物なので手で編集しない。2クローン間で衝突したら `index` で作り直す。

## メッセージの書式

```markdown
---
id: 2026-07-31-1730
from: 設計担当
to: 実装担当
title: lentOnly 案の引き渡し（13枚）
status: 依頼中
---

本文（4KB / 60行以内）

## 返信
受け手はこのファイルの末尾に追記する。ファイルを新しく作らなくてよい。
```

受け手は返信を書いたら `status` を `作業中` / `完了` に更新する。
`done` を打つと `status: 完了` としてアーカイブへ移り、`active/` から消える。
