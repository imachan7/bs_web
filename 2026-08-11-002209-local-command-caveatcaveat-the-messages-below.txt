⏺ フィールドのスピリット数の数え方

  shared/rules.ts に入口が1つに集約されています。

  countSpiritsWeighted(board, countingPid, ownerPid, predicate)

  規約として「効果が『スピリットの数を数える』箇所はすべてこれを通す（素の
  .filter().length
  を使わない）」になっていて、現在22箇所から呼ばれています（EffectModules.ts の
  counter 解決＝「自分の疲労しているスピリットの数×〜」系と、shared/rules.ts
  のオーラ計算）。

  数え上げの重みは spiritCountWeight が1体ずつ返します。

  ┌───────────────────────────────────────────────────────────────────┬─────┐
  │                               状態                                │ 重  │
  │                                                                   │ み  │
  ├───────────────────────────────────────────────────────────────────┼─────┤
  │ 通常のスピリット                                                  │ 1   │
  ├───────────────────────────────────────────────────────────────────┼─────┤
  │ シーサーズ Lv2（countAsMultiple）                                 │ 2   │
  ├───────────────────────────────────────────────────────────────────┼─────┤
  │ スリーカードで印を付けられた1体（countAsThisTurn。相手のスピリッ  │ 3   │
  │ トにも付く）                                                      │     │
  └───────────────────────────────────────────────────────────────────┴─────┘

  なので該当カードが場に無ければ従来と完全に同じ結果になります。

  「自分のスピリット/マジックの効果で数えるとき」という限定のうち、持ち主の判定
  は実装済みです（countingPid === 
  ownerPid。相手の効果が数えるときは1のまま）。抜けているのは「数えているのがス
  ピリットの効果か・ネクサスの効果か・マジックの効果か」の区別だけで、シーサーズ
  は「ネクサス除外」、スリーカードは「マジック除外」が効いていません。

  さっき「影響範囲が広い」と書きましたが、実際に読んだら発生源の種別は取れる場所
  にあります（EffectModules 側は ctx.srcType、shared/rules
  側は発生源インスタンスの getCard().type）。22箇所に引数を1つ足す機械的な作業な
  ので、見立てを下方修正します。やる価値はあります。

  原因

  実装が「1枚破棄 → 即座に1枚ドロー →

  直した内容

  ご指摘の順序どおりにしました。

  1. 破棄するカードをすべて指定する（この間はドローしない）
  2. 破棄が終わったら、その枚数ぶんまとめてドローする

  これで引いたカードは破棄対象になりません。仕組みとしては PendingChoice に
  resolveOnSkip を足して、「選択をスキップした＝もう選ばない」ときにも処理を戻せ

  見つけた穴（本体）

  fireFieldEventTriggers は effectSources（＝いま場にあるもの）だけを走査します
  。そのため「自分のネクサスが破壊されたとき」をそのネクサス自身が持っている場合
  、破壊された時点で場から消えているので無言で発火しませんでした。

  該当は BS07 の各色ネクサス6枚（隕石落下地点・腐りゆく湖沼・大風車の丘・ブリシ
  ンガメンの首飾り・秘密の花園・蹴撃の戦場跡）。

  厄介なのは半分だけ動いていたことです。「自分の他のネクサスが壊れたとき」は場に
  残っているので発火し、「自分自身が壊れたとき」だけ無反応。テストも
  validate:gaps も通り、実装漏れとしても検出されませんでした。

  destroyNexus が破壊されたインスタンスを走査に加えるようにして直しました。6枚す
  べてで発火を確認しています。
