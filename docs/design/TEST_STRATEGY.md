## 2. 案A：場面テスト（CI で毎回回す）— ✅ 2026-10-01 決定。道具と流れは §5・§6

1. **期待値を先に書く**。ルールを知っている側（ユーザー／一次資料）が、実装を見ずに「この場面でこう発動したら盤面はこうなる」を書く

3. **盤面の最終状態で判定する**（ライフ・手札枚数・トラッシュ・カードの位置）
4. **左右反転を自動で走らせる**（p1/p2 を入れ替えて「持ち主側では発動・反対側では発動しない」を1本で見る）

あとで足す候補：AI対戦で「おかしい」と思った瞬間の盤面をファイルに書き出し、そのまま1の開始盤面にする。

## 5. 道具：`scripts/smoke/scenario.ts`（2026-10-01）

- `scenario({ name, start, steps, expect, mirror })`。`start` は「自分（me）／相手（opp）」の開始盤面だけ、`steps` は `t.act("me"|"opp", 操作)`＝handleAction だけ
- 判定は**盤面の写像の差分が `expect` と完全一致**：ライフ・リザーブ・トラッシュのコア・手札・デッキ枚数・トラッシュ・バースト、各個体の場所・疲労・コア・Lv・BP、選択待ち、勝者。
  **書いていない変化も落ちる**ので、対象の取り違え（発生源でなくイベント対象に効く）・余計な発火は、書いた人が見落としていても拾える
- `mirror` は既定で有効。主役を p1→p2 に入れ替えてもう1回走らせる
- 受け入れ確認：#229 前の BS13-X04 のデータで part454 が落ちること（レオが回復せず、味方が疲労したままにならない）
- 写像に無いもの（期間つき効果の残り、シンボル、キーワードの付与など）を見るときは、その行を写像に足す。テストに直接 assert を足して済ませない

## 7. 場面テストで見つからない型と、その拾い方（2026-10-01）

- **経路の組み合わせのバグ**は、1枚の効果文から書く場面テストではまず出てこない。例：竜騎集う円卓＋賢者の樹の実が同時に誘発して順番選択を挟むと、
  発生源のネクサスを見失って色が落ち、【装甲：赤】が抜けた（どちらの効果文にも「もう1枚と並べる」手がかりが無い）
- この型は**不変条件**で拾う：エンジンがどの経路でも守るべき約束を `BS_DEBUG_CHECKS` の検査にし、smoke 全体と AI 自己対戦を検出器にする
  （見失いの検査は導入時に既存 smoke だけで23件を検出した。一覧は RESUME_STACK §5）
- **経路の同値性**（`npm run audit:paths`。2026-11-03）：fieldEvent・step の誘発を1つずつ、単独／同じ条件で誘発する「何もしない相方」と同時に起こして解決順を選ぶ（この効果が先・相方が先）の3通りで解決し、盤面を比べる。人が読む道具（終了コードは常に 0）
  - 検出の確認：#235（`findInstanceAnywhere` がネクサスを探さない）を戻すと、ネクサスが発生源の11枚で42件増える（主体・付帯情報の総当たりを入れる前は5枚・22件）
  - 比べない値：`log`・`events`（操作1回ぶんの演出）・`resumeInsertAt`・`triggerOrderPick`・記録の枠の ID。単独の経路も操作の終わりの後始末（`handleAction`）を通してから比べる（通さないと一時記録の残りが食い違いに見える）
  - 主体（破壊された・召喚されたスピリット）は場の全スピリットを順に試し、効果が実際に誘発した最初の1体を使う。付帯情報（「戦闘で破壊されたとき」の `byBattle` など）も、効果側の条件の欄から作ったものと無しの2通りを試す。主体の条件を検査側で読み直すと、条件の種類だけ穴が残るため
  - 相方からは、確認・支払い・ターンの回数制限・発生源の Lv と合体・「主体が自分自身」の条件を外す（写すと、相方だけ誘発しない・相方の使用記録が食い違いに見える）
  - 範囲：fieldEvent・step の500エントリのうち397件を比べられる（2026-11-03）。残り103件は付帯情報や盤面の条件（系統の体数など）が合わず誘発しない。`SHOW_MISSED=1` で一覧、`ONLY=<cardId>` で1枚だけ回す
  - **アタック宣言から起こす経路**（`VIA=attack`。11-03）：アタック時・『バトル時』・アタックしたとき・疲労したときを、主体に実際にアタックを宣言させて起こす。相方は「スピリットがアタックしたとき、何もしない」。アタック宣言の同時発揮の列（`attackDeclared.ts`）とアタック後バーストを通る。404件中351件を比べられる
    - 検出の確認：#380 より前（アタック時効果が止まると他の誘発が割り込んでいた）では、比べられたのは42件で、273件が「効果は誘発したが相方の確認が立たない」に出る。この数が0でなくなったら、同時発揮の列から漏れた誘発がある
  - **ブロック宣言から起こす経路**（`VIA=block`。11-05）：ブロック時・ブロッカーの『バトル時』・ブロックしたとき・ブロックされたとき・疲労したときを、ブロッカー×アタッカーの組を総当たりして実際にブロックさせて起こす。相方は「スピリットがブロックしたとき、何もしない」。132件中111件を比べられる
    - 主体の候補は、効果が誘発し、しかも相方と同じ列に並ぶものを探す（アタッカーの疲労に「相手のスピリットが疲労したとき」が反応しただけの候補で止まらないため）。それでも相方と並ばない2件（魔星輝く古戦場・呪われし神殿ほか『自分の』『相手の』アタックステップ限定の疲労の誘発）は、ブロックの列で誘発しえないので正しい
    - 検出の確認：#383 より前（ブロッカーの疲労の誘発を列の前に解決していた）では、「効果は誘発したが相方の確認が立たない」が11エントリに増える
  - **召喚から起こす経路**（`VIA=summon`。11-05）：召喚時と「スピリットが召喚されたとき」を、主体（場のスピリット）を手札へ戻して持ち主のメインステップに召喚させて起こす。相方は「スピリットが召喚されたとき、何もしない」
    - 導入時は、誘発した261エントリすべてが「相方が誘発しなかった」に出た（召喚時と「召喚されたとき」を別々に解決していた。同時発揮の列にまとめる修正は別 PR）


## 8. 挙動を変える PR では「変えた条件を読む場所」と「戻すと落ちるか」を表にする（2026-11-12 ユーザー決定）

#453 で「払えるか」の条件を変えたとき、その条件を読む【不死】の道の選択（通常の道／魔門の道）で新しい盤面ができたのに、テストを書かずに出した（#454 で補った）。
直した経路だけをテストし、**同じ条件を読む別の場所**を見ていなかったのが原因。次の3つを PR を出す前の手順にする（`.github/pull_request_template.md` に欄がある）。

1. **呼び出し元の表**：変えた関数・条件を grep し、呼び出し元ごとに「新しく真（偽）になる盤面」と「それを確かめるテスト（part と見出し）」を1行で書く。テストの欄が空の行が残っていたら出さない（変化が無いと判断した行は理由を書く）
2. **戻すと落ちるか**：変えた条件を1つずつ元に戻し、どのテストが落ちるかを書く。落ちない条件は、テストの無い変化
3. **既存テストの期待値を書き換えたら、その変化を正面から確かめるテストを別に足す**：書き換えは挙動が変わった証拠で、書き換えたテストは元の意図（「払えないから出ない」など）を確かめなくなっている

委譲するときは、この3つを完了条件としてプロンプトに貼る。ユーザーは表を見て漏れを確かめる側に回り、足りない所だけテストを書く。
