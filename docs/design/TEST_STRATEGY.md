- **期待値を実装した本人が書いている**ので、ルールではなく実装の写しになる（CLAUDE.md の part36 と同じ）

  発火元の欠落（BURST.md §10 の C）は、イベントを手で呼ぶテストでは原理的に見つからない

同日に機械的に確かめた範囲：`FieldEvent` 37種・`trigger` 13種のうち、本番から発火していないのは `opponentSummonEffectResolved` だけ。

## 2. 案A：場面テスト（CI で毎回回す）

1. **期待値を先に書く**。ルールを知っている側（ユーザー／一次資料）が、実装を見ずに「この場面でこう発動したら盤面はこうなる」を書く
2. **組み立ててよいのは開始盤面だけ**（手札・デッキ・フィールド・バースト）。そこから先は `handleAction` のみ。発火関数の直接呼び出しは禁止
3. **盤面の最終状態で判定する**（ライフ・手札枚数・トラッシュ・カードの位置）
4. **左右反転を自動で走らせる**（p1/p2 を入れ替えて「持ち主側では発動・反対側では発動しない」を1本で見る）

あとで足す候補：AI対戦で「おかしい」と思った瞬間の盤面をファイルに書き出し、そのまま1の開始盤面にする。

## 3. 案B：AI対戦＋Haiku 審判（たまに回す。CI の合否には使わない）

- 打ち手は既存のAI（[AI_OPPONENT.md](./AI_OPPONENT.md)）か fuzz。本物の操作を通り、シード固定で再現できる
- Haiku は**打たせない**（高い・バグを踏む場面へ向かわない・再現できない）。**審判だけ**させる：
  効果の発動時、またはバーストをセット中に事象（ライフ減少・召喚・破壊）が起きた時に、
  カードテキスト・発動前後の盤面差分・ログ行を渡し「効果テキストと食い違うか／発動条件を満たしているか」を聞く
- 価値は**コードを見ずに印刷テキストだけで判断する独立した目**になること。出力は人が見る候補の一覧で、本物だけを案Aの場面テストに落とす
- 限界：細かい裁定（CONJUNCTION.md・TIMING_CHART.md）は知らないので誤検出が出る。費用は作るときに見積もる
