## 3. 【不死】の仕様（2026-08-14 ユーザー確認）

```
【不死：コスト5】『お互いのアタックステップ』
トラッシュにあるこのスピリットカードは、自分のコスト5のスピリットが破壊されたとき召喚できる。
```

- **召喚コストは通常どおり支払う**（「コストを支払わずに」の記載が無いため。軽減も通常どおり。
  払えなければ召喚できない）
- **確認は＞６（破壊処理）のその場で出す**。[TIMING_CHART.md](./TIMING_CHART.md) の＞６に当たる
- ⚠️ **「フィールドに残る」と同時発揮**なので、**ターンプレイヤーが決める順番が結果を変える**:
  - 「フィールドに残る」を先に解決 → その個体は破壊されなかったことになり、**【不死】は発動できない**
  - **【不死】を先に解決できれば発動できる**
- したがって `destroySpiritsFrom` の「順番を聞く候補」を、
  **復活の確認だけでなくその破壊で同時に発揮する効果すべて**へ広げる必要がある
  （現状は `wouldAskReviveConfirm` の下見しか数えていない）
- ⚠️ **【不死】を誘発した「破壊されたスピリット」のシンボルは、その召喚の軽減シンボルに数える**
  （2026-08-14 ユーザー確認）。これは[破壊待機状態](./TIMING_CHART.md)の帰結で、
  **【不死】の解決を破壊待機の窓の中に置く**ことで自然に満たされる（特別扱いは要らない）。
  同じ理由で、**破壊待機状態のスピリットを【転召】の生贄にもできる**
- `【不死：コスト6/7】` `【不死：コスト3/4/5/6】` のように**引き金のコストは複数指定**がある。
  無印の `【不死】`（BS09-013 等が参照する側で使う）はキーワード保持の判定にだけ使う

## 4.5 実装で確定した規則（2026-08-14）

- **【不死】による召喚も「召喚」である。** 『このスピリットの召喚時』だけでなく
  「自分のスピリットが召喚されたとき」のフィールド誘発も通常どおり起こす
  （`applyFushiSummon` が `fireSummonSequence` を呼ぶ。以前は召喚時効果しか発揮していなかった）。
  「**【不死】の効果で召喚されたとき**」（BS09-013 ミミズクロ）だけを拾いたいときは
  `fieldEvent.fushiSummonOnly` を付ける
- BS09-071 イモータルドローの「**【不死】を持つ**自分のスピリットが召喚されたとき」は、
  召喚の手段を問わない（手札からの通常召喚でも発揮する）。効果文が召喚の手段を限定していないため

- **「Lvコストを+1する」は、各レベルに必要なコア数を+1する**（BS09-017 蛇凰神バァラル Lv2-3。2026-08-14 ユーザー確認）。
  **Lv1 のコストも上がる**ので、コアが足りなくなった個体は**維持コア割れで消滅する**。
  実装は `CardInstance.levelCostBonusContinuous` →`shared/rules.instLevels` の1本道で、
  レベル・BP・維持コアがまとめて追随する。
  消滅の掃除だけは「コアが減ったとき」の各判定では拾えないため、
  `EffectModules.sweepLevelCostDepletion` を `handleAction` の事後フックで回す
  （＝プレイヤーに手番が戻る地点でまとめて解決する）
- **BS09-058 魔本収められし書架 Lv2 の「相手のデッキが0枚のとき、この効果は発揮されない」は
  印刷テキストどおりに実装する**（2026-08-14 ユーザー確認。誤記の疑いを相談したが、そのままでよいとの判断）。
  `step.condition.opponentDeckNotEmpty`

## 4.7 実装で置いた解釈（要確認ではないが、根拠を残す）

- **BS09-077 アイスバーグ「【氷壁】の効果は『自分のターン』に発揮される」は「置き換え」として実装した**
  （相手のターンでは発揮しなくなる）。「〜に発揮される」を追加でなく移動と読んだため。
  `magicNegateTurnOverrideGrant`
- **BS09-062 ノルンの泉の「ネクサス1つを代わりに疲労させる」は、回復状態のネクサスがあれば常にそちらで払う**
  （スピリットを回復状態のまま残す側に倒す決定的簡略化）。`magicNegatePayByNexusGrant`

## 4.8 黄バッチで確認した規則（2026-08-14 ユーザー確認）

- **対象の付け替え（`magicTargetRedirect`）はマジックに限らず、対象を選ぶ効果全般に効く。**
  効果文が「スピリット/マジックの効果」なので、スピリットの効果も拾う（ネクサスの効果は通る）。
  実装は `resistanceAgainst` の絞り込み判定を `sourceType === "magic" | "spirit"` へ広げ、
  `fireTrigger` がスピリットの誘発を解決する前後で `setTargetRedirect` を掛けるようにした。
  **BS05-040 プリンセス・スノーホワイトの挙動も同時に正しくなる**
  - ⚠️ 付け替えは「守る対象を候補から外す」形なので、**明示的に対象を指定された場合は不発になる**
    （付け替え先へ移し替えるのではない）。これはマジック版から変わっていない
  - ⚠️ 「〜にできる」の任意性は、スピリットの効果では確認を出さず自動適用にしている
    （誘発の中断・再開の口が別なため。マジック版は従来どおり確認を出す）
- **BS09-063 花の宮殿の支払い「コア1個をトラッシュに置く」は、コア1個の個体でも支払う。**
  破壊待機中はコアが乗ったままなので支払いは成立し、待機解除の直後に維持コア割れで消滅する
  （`reviveOnDestroy.cost.oneCoreToTrash`）
- **BS09-039 探偵ペンタンの「相手の手札1枚の内容を見る」はサーバー側だけ先に入れた。**
  見たカードは `PlayerView.peekedOpponentCardIds`（持ち主にだけ返す）。
  裏向きの相手手札から選ぶUIは未実装のため、**選ぶ1枚は先頭で固定**している
  （どれを選んでも情報量は同じなので不公平にならない）。UIは chatbox `2026-08-14-1900` で依頼済み

## 4.9 青・緑バッチで確認した規則（2026-08-14 ユーザー確認）

- **BS09-049 炎蜥蜴クトゥグマの「「ブロックされない」効果を持つ相手」は、継続的な制約
  （`unblockableBy`）と**ターン限定の印**（`unblockableOnceThisTurn`）の**両方**を指す
  （＝「いまこのスピリットがブロックできない状態にしている相手」）。
  `constraint:"canBlockUnblockable"` と `TargetFilter.unblockableOnly`
- **BS09-052 フォレスト・ゴレムの「コスト3/4のスピリット1体ずつ」は、コスト3から1体・コスト4から1体（計2体）。**
  片方しかいなければその1体だけ（`destroyCostsEachOne`）
- **BS09-065 名工集いし大工房 Lv2 は、フィールドのコア「だけ」で配置コストを払う**（リザーブは使わない）。
  取るのはネクサス上→コアの多いスピリットの順で、維持コアを割る個体からは取らない（決定的簡略化）
  - ⚠️ 前提の確認：**ネクサスの配置コストは、通常も `setNexus` の `paySources` でフィールドのコアから払える**
    （召喚と同じ `payCost` を通る）。この効果はそれを「フィールドのコアだけ」に限定する形
- **「Lv1コスト」＝Lv1に必要なコア数**（レベル表の「Lv1コスト：1」の表記。2026-08-14 ユーザー確認）。
  `coreFloorByCost` は**カードの召喚コストとして実装されていた誤り**があり、ここで直した。
  **BS09-059 翡翠の社 Lv2 と BS08-059 聖なる柱状彫刻の両方の挙動が変わる**（保護が弱くなる方向）

## 5. 進め方

1. 新しい器（§2 の6件）を先に入れる。**#1【不死】が最大**で、順番の選択（§3）に手を入れる必要がある
2. そのうえで91枚を構造化する。色ごとのバッチに分けると編集ファイルが重ならない
3. 完了条件は定型どおり:
   `typecheck && validate:cards && validate:notes && validate:gaps && smoke:quiet && build:client`
4. 弾がまるごと入り終わったら `npm run coverage:effects` を1回回し、
   実行実績0の効果エントリ（＝smoke の穴）を潰す
