# 「相手の〈色〉の効果で〜されたとき」を見る仕組み

**「〜の効果で」を条件にする誘発を足すときに読む。** 2026-08-16 に SD01-029 蠢く地下墓地と
SD01-031 朝焼け岬のために入れた。

## 1. 何が問題だったか

この2枚は「**相手が〈色〉のスピリット/ネクサス/マジックの効果で**〜したとき」という形をしている。

```
SD01-029 蠢く地下墓地 Lv1『相手のターン』
  相手が緑の効果で、コアを相手のフィールド/リザーブに置いたとき、置いたコア1個につき…
SD01-031 朝焼け岬 Lv1『相手のターン』
  相手の紫の効果で、相手の手札にカードが加えられたとき、そのカード1枚につき…
```

ところが発火点は**誰の効果で起きたのかを知らない**。
`notifyHandGained` は15箇所から呼ばれていて、その中には**ドローステップの通常ドロー**も入っている。
色で絞る以前に「効果によるものか」すら区別できていなかった。

## 2. 仕組み：`GameState.currentEffectSource`

`resolveAction`（**全効果アクションの唯一の入口**）が、ハンドラを呼ぶ間だけ発生源を state に載せる。

```ts
currentEffectSource?: { pid: PlayerId; type?: "spirit" | "nexus" | "magic"; colors?: Color[] }
```

- ネストした `resolveAction` は自分の値で上書きし、抜けるときに前の値へ戻す
- **効果によらない動き**（ドローステップ・コアステップ・コスト支払い・リフレッシュ）は
  `resolveAction` を通らないので `undefined` のまま。これだけで「効果によるものか」が分かる

カード側は `fieldEvent.sourceColorFilter` を書く。判定は次の3つをすべて満たすこと:

| ① | 効果の解決中に起きた（`currentEffectSource` がある） |
| ② | その効果の持ち主が発生源の持ち主ではない（＝「**相手の**」効果） |
| ③ | その効果の発生源がこの色を持つ（多色は1色でも含めば一致） |

`colorFilter` が「イベント**対象**の色」を見るのに対し、`sourceColorFilter` は
「効果の**発生源**の色」を見る。この2つは別軸なので併用できる。

## 3. コアが置かれたことの検出（`opponentCorePlaced`）

手札の増加は既存の `notifyHandGained` に相乗りできたが、**コアの配置には通知が無かった**。
コアが増える箇所はエンジン中に**28箇所**ある。

**全部に通知を足すのは採らなかった。** RESUME_STACK.md §5(a) と同じ
「呼び出し元が対応していない」問題を28箇所ぶん抱えることになり、
将来コアを置くコードを書いた人が必ず忘れるため。

代わりに `resolveAction` の**1箇所**で、効果1つの前後にコアの居場所を突き合わせる。

```
snapshotCorePlaces()  … 各プレイヤーの reserve と、各インスタンスの cores を控える
     handler(ctx, action)
fireCorePlacedFromDiff() … 増えた側だけを合計して "opponentCorePlaced" を発火
```

**数え方は「増えた側だけの合計」**（減った側を差し引かない）。効果文が出所を限定していないため、
リザーブからスピリットへ移したものも、スピリットからスピリットへ移したものも**1個**と数える
（2026-08-16 ユーザー確認）。差し引くと移動が0個になってしまう。

守っている約束:

- スナップショットは**一番外側の効果でだけ**取る（ネストで取ると同じ配置を二重に数える）
- 監視するカード（`opponentCorePlaced` を持つカード）が場に1枚も無ければ、
  スナップショット自体を取らない（`hasCorePlacedWatcher`）。毎アクション走る経路なので
- 発火は `currentEffectSource` を戻す**前**に行う（`sourceColorFilter` がそれを読むため）

## 4. 限界（分かったうえで許容している）

- **選択待ちで中断をまたぐと目印は失われる。** 効果の途中で `pendingChoice` が立つと、
  その時点までの差分で発火し、再開後のぶんは別の効果として数えられる。
  該当カードは1枚だけで、実害が出る組み合わせは見つかっていない
- `sourceColorFilter` は「**相手の**効果」を前提に組んである（②の pid 判定を内蔵）。
  「自分の〈色〉の効果で」を書きたくなったら、そこを軸として外すこと
