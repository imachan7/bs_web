## 0. この弾の性格

**新しいキーワードは1つも無い。** 出てくるのは【合体時】26 /【重装甲】7 /【不死】6 /【超覚醒】4 /
【呪撃】4 /【神速】4 /【転召】4 /【氷壁】2 /【強襲】2 /【合体中】2 /【激突】1 /【光芒】1 で、すべて実装済み。

代わりに**既存キーワードの引数が増える**のと、**ブレイヴの扱いがさらに一歩進む**のが主題:

1. **【不死】の条件指定**（2枚）— これまでの【不死】は無条件だったが、
   **【不死：コスト7/8】**（BS13-012）と**【不死：妖蛇】**（BS13-014）が出る。
   「何が破壊されたとき蘇るか」をコスト／系統で絞る
2. **スピリット状態のブレイヴへの干渉**（5枚以上）— アタック時に合体する（BS13-007）、
   ブレイヴ同士を合体させる（BS13-049）、相手のブレイヴだけを破壊する（BS13-X06）
3. **色を無いものとして扱う**（3枚）— BS13-011 / 015 / 052。色を**足す**のはあったが**消す**のは初出
4. **本来のコスト**（BS13-003）— 軽減前のコストで判定する軸

## 1. 確定した解釈

| # | 論点 | 確定 |
| :-- | :-- | :-- |
| 1 | BS13-007「合体できる。**その後**〜『合体アタック時』効果を発揮させる」 | 「その後」＝前後関係。**合体しなければ発揮しない**（2026-09-07 ユーザー確認） |
| 2 | 同上：**既に別のブレイヴが合体した状態**でアタックし、さらに1つ合体したとき | **新しく合体したブレイヴの効果だけ**発揮する（2026-09-08 ユーザー確認）。先に合体していたぶんはアタック宣言の時点で発揮済みなので、この効果は「宣言に間に合わなかった分を拾う」もの。二重発揮させない |
| 3 | BS13-049 が借りた効果の中の「このスピリット」 | **発揮する側（イリテバン）** を指す（2026-09-07 ユーザー確認） |
| 4 | BS13-005「分離できず、**お互い**、その上のコアは取り除けない」 | **「お互い」はコア除去にだけかかる**（2026-09-07 ユーザー確認）。分離禁止は主語なしで自然に両陣営 |
| 5 | X011「Lv1/Lv2/Lv3BP を12000として扱う」 | **場にいる間ずっと実効BPが12000**（2026-09-08 ユーザー確認）。BS12 の `setBattleBpFixed` はバトル中だけなので継続版が要る |
| 6 | 同上：置き換わるのは**印刷BPだけ**か、実効BP全体か | **印刷BPだけ**。効果文が「Lv1/Lv2/Lv3**BP**を12000として扱う」とレベルごとの印刷BPを名指ししているので、そのあとの BP+（ブレイヴの合体時BP+・オーラ・一時BP+）は12000の上に乗る。`battleBpFixed`（「BPを◯として扱う」＝実効BPごと固定）とはここが違う |
| 7 | BS13-061「BP4000以下のスピリットがアタックしたとき破壊する」 | **両陣営**（2026-09-08 ユーザー確認）。同じ弾の BS13-006 が「**相手の**スピリットが」と明記しているのと書き分けられている。自分のスピリットも破壊される |
| 8 | BS13-049 の「ブレイヴ同士の合体」で、できた塊はさらに合体できるか | **できない**（2026-09-08 ユーザー確認）。ブレイヴが乗った塊は、別のブレイヴを受けることも、本物のスピリットへ合体することもない＝**実体の入れ子は2段で止まる** |
| 14 | BS13-X03 Lv1-3「ブレイヴカードを召喚するとき、疲労状態で召喚する」でダイレクトブレイヴ（合体させて召喚）したとき | **合体先のスピリットが疲労する**（2026-09-08 ユーザー確認）。ダイレクトブレイヴは合体した状態で場に出るので実体は合体スピリット。合体時の疲労合成の規則（TIMING_CHART §1.3）とも整合する |
| 15 | BS13-X03 Lv3「**スピリットすべて**のコアは【転召】以外で取り除けない」の範囲 | **両陣営。自分のスピリットも対象で、自分の効果のコスト（コアをトラッシュへ置く等）も払えなくなる**（2026-09-08 ユーザー確認）。例外は【転召】だけ |
| 16 | BS13-053「このブレイヴを**回復させ、**そのスピリットに**合体できる**」 | **回復と合体はセット**（2026-09-08 ユーザー確認）。「できる」は効果全体にかかる任意で、発揮するなら両方行う。合体できない（合体条件を満たさない等）なら回復もしない |
| 10 | 「このスピリットの色を無いものとして扱う」（011 Lv2 / 015 Lv2 / 052【合体時】） | **色とシンボルの両方が無色になる**（2026-09-08 ユーザー確認。2018年ルールマニュアル Ver.9.0 で「色を無いものとして扱う」→「色とシンボルは無色として扱う」に改定）。**そのスピリットのシンボルはどの色の軽減にも使えなくなる**。ライフ減少の枚数はシンボル数なので変わらない |
| 11 | BS13-011 Lv2『このスピリットのアタック時』の無色化はいつまで続くか | **そのバトルの終了まで**（2026-09-08 ユーザー確認）。`battleBpFixed` などと同じ寿命＝`clearBattle` でリセット |
| 12 | BS13-052 が借りた『破壊時』効果の「このスピリット」は誰か | **効果を持っているスピリット自身**（2026-09-08 ユーザー確認）。049（「このスピリットの効果として発揮できる」と明記あり）とは逆。**さらに、そのスピリットの現在Lvで有効なエントリだけ**が候補（Lv2の破壊時効果は、そのスピリットがLv2のときだけ発揮できる） |
| 13 | BS13-075「このターンの間、〜されたとき〜する」の回数 | **回数制限なし**（2026-09-08 ユーザー確認）。そのターン中、自分のスピリットが破壊されるたびに、コアを払えるかぎり毎回発揮できる |
| 9 | BS13-049 の借り元候補に**イリテバン自身**が入るか | **入る**（2026-09-08 ユーザー確認）。自身を選ぶと同じ効果がそのアタックで2回発揮される。ただし**2回で止める**（再帰的にまた自身を選べると無限に連鎖するため） |

## 4. バッチ割り（案）

BS12 と同じく**色ごと**。X005 系6色（A/D/E/S/T の5枚。**赤の X005R は BS10 に収録済みなので取り込まない**）は

| :-- | :-- | :-- |

## 5. ⚠️ 取り込みで踏んだこと

- **`X005R` は BS10 に既に収録されている**（Wiki が両方の弾に載せている）。staging から除外した。
  同じことが起きうるので、**取り込んだら必ず既存 cardId との衝突を検査する**
- **X005A/D/E/R/S/T は同一カードの6色違い**（「北斗七星龍ジーク・アポロドラゴン」）。
  デッキの上限は**カード名で合算**するので（`GameState.ts` の同名上限）、
  6色あっても**デッキには合計3枚まで**。実装側の追加対応は要らない
- 接頭辞を持たない X カード（X005系 / X006 / X011）は既存の命名どおり（X003D / X004 / X005R / X007 / X008）。
  `BS13-` を付けないこと

## 6. バッチ1a（赤・前半8枚）で足した器

`addSymbolPermanent`（本来のコストでの判定＝器C）／`combineOwnBrave`（`hostSelf` ＋
`thenFireWhileCombinedTrigger`＝器D。§1 #1・#2）／`destroyByBpBudget`（系統のBP合計まで＝器J）／
`awakenFromReserve` の `superAwakenOnly`（器N）／`cantSeparate`（器O）／
`returnOwnSpiritToHand`／`refreshSelfByReturnToHandFamily`。

**`refreshSelfByReturnToHandFamily` は独立アクションで正しい。** 2026-09-08 に一度
「`refreshSelf` のコスト軸へ畳むべきだった」と書いたが、**これは誤り**だった。
`refreshSelfByDestroyFamily`（「破壊することで回復する」）が BS08 の頃から独立アクションとして
存在しており（BS02-X07 巨神機トールが使用）、「〜することで回復する」を独立アクションで表すのは
**この codebase の確立されたパターン**。コスト軸へ畳むと同じ形に2通りの書き方ができて不整合になる。

⚠️ 一方 **`returnOwnSpiritToHand` は `returnToHand` に自分側限定の軸を足すほうが小さく済んだ**
（既存は `anySide` があるだけで自陣限定が無い）。差は小さいので作り直してはいないが、
次に自陣限定の手札戻しが来たら `returnToHand` を広げること。

**教訓: 「既存の器を広げるべきか、兄弟アクションを足すべきか」は、その形に前例があるかで決まる。**
前例（兄弟アクション）があるならそれに揃える。無いなら既存を広げる。

### ⚠️ ここで潰したバグ

- **スピリット状態のブレイヴが「自分自身と合体」できてしまった**。ブレイヴが合体先にもなれるように
  なった結果、候補の絞り込みを1か所忘れると `braveRefs` が自分を指す壊れた盤面ができる。
  `combineOwnBrave` の両経路で自身を外し、**`attachBrave` に `host === brave` の最終防波堤**を置いた
- **`bpAs` が BP+ を全部飲んでいた**（`effectiveBp` の早期 return）。§1 #6 のとおり印刷BPだけを置き換える形に直した
