# 先読みが旧に負ける理由（2026-11-20、構築済みデッキの新旧対戦 25局×48組=1200局）
記録: BS_AI_TRACE=path（ai-bench のみ。lookahead.ts の setLookaheadTrace）。データ: scratchpad の smc2.jsonl（召喚・配置・コア 1200局）、all.jsonl（全部 745局で中断）。集計 an.py / an2.py。
## 結論（事実）
1. 基準値の偏り: lookaheadPick は base（実局面）+9 を超えた試行だけ採るが、試行は決定化で相手の手札が空。手札項(5×min(枚数,6))が試行側だけ平均+15〜20 有利。何を打っても base+9 を超える。smc では上書き 4744 件の chosen−base 中央値 23、偏りを引くと 5（40%だけが+9以上）。
2. 旧の手が比べられていない: 旧の手の種類が KINDS 外（nextPhase・castMagic）だと試行されず、moveCore/summon が base 比較だけで旧の手を上書きする。smc 上書きの 37%（1751/4744）。nextPhase→moveCore 1336件は新の勝率 21.9%。moveCore 上書きが 6回以上の局は勝率 8.1%（0回は52.0%）。
3. 同点崩し: 全部の記録で上書きの 94% は chosen−旧の試行値が3以下（中央値0）。旧の点表の選択を列挙順の先頭で置き換えているだけ。
4. 評価が資源を使う手を嫌う: 召喚・マジックは手札-5・リザーブ1個-6(場+2) を払う。moveCore は1個-4だけ。BS-AI の例（1-1 T6, 0-3 T4）で moveCore が旧のマジックより高く出た。何もしない手が最高になりがち。
## 追試（smc、1200局、新の勝率）
基準 39.1% / base を決定化複製で測る 46.0% / 旧の試行値+10 を要求 47.1% / MARGIN=30 46.3% / 両方 47.8%（45.0〜50.7）。偏りと旧との比較を直しても 50% には届かない＝4 が残る。
## 負けた局

## 直す候補
1. 比較の条件をそろえる: base を決定化複製で測り、旧の手の試行値+margin を要求（旧の手の種類は KINDS 外でも試行）。47.8%まで。
2. 評価: 資源を使う手の評価（手札-5・コア-6 に対し場の見返りが足りない）。展開を正しく評価できるまで moveCore を候補から外すのも可。
3. 旧の手との同点は旧に任せる（1 に含まれる）。
