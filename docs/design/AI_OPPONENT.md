# AI対戦相手の設計（2026-08-23）

**AI の強さを変えたい・AIが変な手を打つのを直したいときに読む。**
実装は `server/src/ai/`（4ファイル・約350行）。方針は 2026-08-23 のユーザー判断で
「**ルールベースの1手評価**（先読みなし）」に決めた。

## 1. なぜこの作りか

強さより **止まらないこと** が要件。AIが手を選べずに固まると、対戦者は画面の前で
何も操作できないまま待たされる（相手が人間なら「切断」で片が付くが、AI戦には逃げ道がない）。
そのため次の2つを設計の芯に置いた:

- **合法手は必ず1つ以上残る**。メインなら `nextPhase`、アタックステップなら `endTurn`、
  フラッシュなら `pass`、選択待ちならスキップが常に候補に入る
- **可否の判定を自前で書かない**。`RuleValidator` の `validateXxx` は副作用のない検証関数なので、
  候補を作っては捨てる用途にそのまま使える。「AIが打てるつもりの手をサーバーが弾く」ズレが構造的に起きない
  （クライアントUIが `activatableAbility` を通してボタンを出すのと同じ考え方）

## 2. 3つの層

| ファイル | 役割 | 入力 |
| :-- | :-- | :-- |
| `legalMoves.ts` | 今打てる手をすべて列挙する | `GameState`（`validateXxx` が要求するため） |
| `evaluate.ts` | 1手ずつ点数を付ける | **`GameView`**（AI自身の視点） |
| `runner.ts` | 対戦中に1手ずつ進める・安全弁 | `GameState` |
| `index.ts` | 上2つを繋ぐ `decideAiAction` | — |

### ⚠️ AI に相手の手札を覗かせない仕組み

**評価関数が受け取るのは `GameState` ではなく `GameView`**（`viewFor(state, pid)` の結果）。
GameView は相手の手札・デッキ内容を持たないので、AIが盤面の裏を見て指すことが型の上で起こらない。
これが成立するのは `shared/board.ts` の `_GameViewIsBoard` があるおかげで、
共有ルール層（BP計算・ブロック可否・コスト）を GameView のまま呼べる。

**評価に `GameState` を渡す形へ変えないこと。** 一度渡すと、相手の手札を見た判断が
いつのまにか混ざっても誰も気づけなくなる。

列挙のほうは `GameState` を使うが、`validateXxx` は「その手が合法か」しか答えないので
情報の非対称は生まれない。

## 3. 点数表（`evaluate.ts`）

高いほど打ちたい手。同点なら列挙順（＝決定的に選ぶ）。

| 手 | 点数 | 補正 |
| :-- | :-- | :-- |
| アタック | 100＋BP/1000 | 止める相手がいない +60（相手ライフ1なら +300）／返り討ちにされる相手がいる −50／**守りが残らない −130** |
| 召喚 | 80＋BP/1000＋シンボル×5 | 払える最大レベルで出す |
| 起動能力 | タグで決まる（下記） | マジックと同じ点数表。タグは moveTags.ts が効果の形から付ける |
| コアを置く | レベルが上がるなら75／上がらないなら5 | 上がらないコアはリザーブに残す |
| ネクサス配置 | 60 | |
| マジック | タグで決まる（下記） | 足切り：バトル外の `battleOnly`・相手の場が空の `removal`・自分のスピリットがいない `buffOwn` は候補から落とす |
| ブロック | 相手より強い150／相打ち60／負ける10（自ライフ2以下なら70）／自ライフ1なら200 | |
| ライフで受ける | 20＋ライフ×15（ライフ1なら0） | ブロックの点数と釣り合わせてある |
| フラッシュをパス | 40 | |
| アタックステップへ | 20 | |
| ターン終了 | 5 | 他に何も無いときだけ |
| 選択待ちへの応答 | 下記 | |

マジック・起動のタグ別の点（`removal`＞`battleOnly`/`buffOwn`＞`draw`＞`unknown` の順で当てる）:
`removal` は 60＋相手の最も強い個体のBP(千)×5（上限110。対象を指す手はその個体で計算し、自分の個体は5）／
`buffOwn`・BP+ を持つ `battleOnly` はバトル中に自分のバトル中の個体がBP+で逆転できるなら120・それ以外30・バトル外15／BP+ を持たない `battleOnly`（守り）はアタックを受ける側なら90・アタック側なら15・バトル外15／
`draw` はメイン50・フラッシュ45／`unknown` はメイン25・フラッシュ35。

**選択待ち（`resolveChoice`）は候補の持ち主で符号を変える**のが基本則。
同じ `resolveChoice` で「相手のものを選ぶ場面（破壊・疲労）」と
「自分のものを選ぶ場面（コスト・破棄）」の両方が来るため:

- フィールドの個体：相手のものなら強い個体（50＋強さ）、自分のものなら弱い個体（50−強さ）
- 手札のカード：**軽い**カードを出す（破棄・コストの場面が多い）
- トラッシュ／公開ゾーンのカード：**重い**カードを取る（回収・召喚の場面が多い）
- 「〜できる」の発動確認（`confirm`）：80（＝発揮する側に倒す。ここを下げるとAIが何も撃たなくなる）
- スキップ：20（他に選ぶものがないときの最後の逃げ道）

### 「守りを1体は残す」だけは補正が大きい理由

アタックしたスピリットは疲労してブロックに回れない。1手だけを見る評価ではそれが見えず、
両者が全員で殴り合って **平均5.0ターンで決着**していた（2026-08-23 の自己対戦30試合）。
「この体で殴ると回復状態の味方が0になり、相手に回復状態のスピリットがいて、相手ライフが2以上」
のとき −130 する補正を入れて平均6.0ターンになった。
今ターンで削り切れる見込み（相手ライフ1）のときは温存しない。

## 4. 安全弁（`runner.ts`）

| 仕掛け | 目的 |
| :-- | :-- |
| `pumping`（WeakSet） | 同じ対戦でループが二重に走らない。人間の action と AI 自身の action の両方から `pumpAi` が呼ばれるため |
| 弾かれた手を覚える | サーバーに拒否された手を避けて選び直す（同じ手を選び続けて止まるのを防ぐ）。8回続けて拒否されたら降参して対戦を終える |
| `MAX_ACTIONS_PER_PUMP`（400手） | 「打っても盤面が進まない手」を選び続けたときにサーバーを回し続けない |
| `isActive()` | 相手が切断してルームが破棄されたら止まる |

`AI_STEP_DELAY_MS`（既定450ms）が1手ごとの間隔。**`BS_AI_DELAY_MS` で上書きできる**
（E2E は 0 で回す）。

## 5. 既知の限界

直すときはここから。**いずれも「弱い」だけで、対戦が壊れるものではない**。

- **先読みがない**。打った後の盤面を評価していないので、コンボや複数体での詰めは組めない。
  状態を複製して1手先を読む案は見送った（効果解決の副作用まで正しく巻き戻せる保証がないため）
- **マジックの効果の中身を読まない**。撃てるフラッシュマジックはだいたい撃つので、
  リザーブ0で【覚醒】マジックを撃つような空振りが起きる。効果の意味づけをAIに教える仕組みは無い
- **選択待ちの意味を読まない**。prompt の日本語は解釈せず、候補の持ち主とコストだけで決める
- 平均6ターンで決着する（自己対戦）。人間相手なら妥当な速さだが、盤面を作り合う展開にはなりにくい

## 7. 強化の段階 0・1（#640。2026-11-19 着手）

issue #640 のロードマップのうち、先読みなしで済む段階 0・1。K1〜K4 は issue の推奨どおり（先読みは段階3、段階0〜2で区切る、意味タグは AI 側の分類から）。

### 段階0：測定の道具 `npm run ai:bench`（`scripts/ai-bench.ts`）

定型の検証には入れない（自己対戦を何十局も回すため）。AI を触ったら前後で回して比べる。
- 6色の総当たり（同色を含む21組）を各 N 局（既定 3）。`createGame(seed, names, { p1: 色, p2: 色 })` のスターターデッキ、`interactiveTargets = true`、`pumpAiSync` で決着まで（part225 の自己対戦と同じ組み方）
- 出すもの：局数・平均ターン・詰まり（両者とも手が無い）・例外・手の種類ごとの回数、そして**無意味手**の回数
  - バトル外で使った「このバトルの間」だけのマジック（タグ `battleOnly`）
  - 使ったが「対象がいなかった」で何もしなかったマジック・起動（ログで数える）
  - メインステップで使ったフラッシュの守りのマジック（タグ `battleOnly` かつメインステップ）
- 乱数は `Math.random` のままなので、局数で均す。比べるときは同じ N で

### 段階1：無意味手をやめさせる

1. **手に効果タグを付ける**（新しいファイル `server/src/ai/moveTags.ts`）：`castMagic`（使う timing の効果）・`activateAbility`（その起動効果）について、カードの構造化された効果（`effects` の action の木）から機械的に付ける。カード ID で分岐しない
   - `battleOnly`：効果がすべて「このバトルの間」（timedEffect の duration が battle）か、バトル中のスピリットを対象にするもの
   - `removal`：相手のスピリット・ネクサスを破壊・手札/デッキに戻す・疲労・BPマイナス・コア除去
   - `buffOwn`：自分のスピリットの BP+・回復
   - `draw`：ドロー・コアを増やす
   - `unknown`：上のどれにも当たらない
2. **足切り**（合法手から落とす。`pass`・`nextPhase`・`endTurn` は落とさない）：`battleOnly` をバトル外で／`removal` で相手のフィールドに対象になれるものがいない／`buffOwn` で自分のスピリットがいない
3. **点数を「何もしない」手との比較で付け直す**：マジック・起動の固定点（45/65/70）をやめ、タグで付ける（2026-11-19 の bench を見て直した最終値）
   - `removal`：60＋相手の最強BP(千)×5（上限110）。対象を指す手はその個体で計算し、自分の個体なら 5
   - BP+ を持つ `battleOnly`／`buffOwn`：バトル中に自分のスピリットが今は負けていて BP+ で逆転するなら 120、そうでなければ 30（パス 40 より下）。バトル外は 15
   - BP+ を持たない `battleOnly`（バトル終了・BP比較を飛ばす等）：相手のアタックを受けている側なら 90、自分がアタックしている側やバトル外は 15
   - `draw`：メインステップ 50、フラッシュ 45（パスより上）
   - `unknown`：メインステップ 25、フラッシュ 35
   - 当初の案（守りの battleOnly を一律 30・フラッシュのドロー 30）は、bench で守りとドローを全く撃たなくなったので直した
4. **対象の選び方**：`removal` のマジックの対象は、相手の強い個体から（今は列挙の順で最初の個体）

段階1を入れる前と後で `ai:bench` を回し、無意味手の回数と平均ターン・詰まり0・例外0を PR に書く。

2026-11-19 の結果（63局）：平均ターン 6.0→6.1、詰まり・例外 0、「対象がいなかった」12→4、マジック 141→116 回（BP+ 33→3、守り 10→13、ドロー 15→16）。「バトル外の battleOnly」「メインでの守りのフラッシュ」はスターターデッキでは前後とも 0 件で bench では検出できない（part1012 で押さえた）。「対象がいなかった」の残り4件は原因未調査

### 8.2 evaluateBoard の式（案）

`evaluateBoard(view, me) = side(me) − side(opp)`。相手の手札は見えないので **手札は枚数だけ**。勝敗が付いていれば ±100000（`view.winner`）。ライフ0は勝敗に至る前の局面でも ±大にせず、ライフ項で急に重くする（ライフ1の価値が高い）。

| 項目 | 式（初期値） | 根拠 |
| :-- | :-- | :-- |
| ライフ | 20×ライフ＋ライフ1以下なら−40 | ライフ0が負け。最後の1つは落ちやすさが段違い |
| 場のスピリット（1体ごと） | 3×BP(千)＋8×シンボル数＋（回復状態なら＋6／疲労なら0） | シンボル数＝1回のアタックで削る数＝打点。回復状態は次の相手ターンのブロッカー |
| 回復状態の個体が0で相手に打点あり | −25 | 既存の「守りを1体は残す」(−130)の置き換え先 |
| ネクサス | 10＋レベル×4 | 効果は読まないので控えめ |
| 場のコア（スピリット・ネクサス上） | 2×個数 | レベル・維持。ただし BP・レベルの項と二重にならないよう低く |
| リザーブのコア | 3×個数（上限8個で頭打ち） | 次ターンの召喚・コスト軽減の原資。余らせすぎは価値が薄い |
| トラッシュのコア | 0 | 盤面外 |
| 手札の枚数 | 5×枚数（上限6） | 展開の原資。自分は中身が見えるが、相手と釣り合わせるため枚数だけ |
| デッキ残り | 残り5以下で−（5−残り）×15 | デッキ切れ負けの回避だけ。通常は0 |

重みは初期値で、`ai:bench` の新旧対戦（8.5）で調整する。**重みは1つの定数オブジェクト（`BOARD_WEIGHTS`）にまとめ**、旧 AI との比較・調整で差し替えられるようにする。BP は `effectiveBp`、シンボルは `instanceSymbolCount`、レベルは `currentLevel`（いずれも共有層で GameView のまま呼べる。既存 boardStrength と同じ）。

### 8.3 段階2で evaluateBoard を使う場所

先読み不要で結果盤面を手で作れる判断だけ。作り方は「GameView を `structuredClone` して該当個体の状態（疲労・破壊・コア）だけ書き換えて採点」でも、差分を直接足す形でもよい（後者を推奨。複製は段階3のものと別物にしない）。

| 判断 | いまの決め方 | evaluateBoard の差で決める形 | 変わる見込み |
| :-- | :-- | :-- | :-- |
| ブロックするか・どれで | 点表（8.1 のブロック行）。個体は BP が上の物が高点、同 BP は列挙順 | 各手（各ブロッカー／ライフで受ける）の結果盤面を作り評価の差で比較。ブロック＝BP比較で負ける側を除去し、受ける＝ライフ−1（相手の効果は無視）。ブロッカー同士の選択は「破壊されない中で最も価値の低い個体」を自然に選ぶ | 大。いまは「相打ちを避けたい／強い個体で受けたい」が表現できない |
| アタックするか・どれで | 点表（8.1 のアタック行）。固定補正3つ | 各アタッカーについて、相手の最良のブロック（ブロック可能な各個体＋受けるの中で評価が最も低くなる物）を仮定した結果盤面の評価−現在の評価。ブロック不可なら相手ライフ−1。全員が回復状態でなくなる項は評価側が持つ | 大。-130 等の手当てが評価の項に吸収され、複数体のアタック順も差で決まる |
| コアを置く対象・置くか | レベルが上がるなら75、上がらなければ5。対象は列挙順 | 各個体にコア+1した盤面（BP・レベル・シンボルの変化）を評価し、リザーブ−1の項と差し引きして、パス（置かない）との差が最大の手 | 中。BP/シンボルが最も増える個体に置く |
| 召喚するレベル・対象 | 最大レベルのみ列挙 | 段階2では変えない（コア配分が手に出ないため）。列挙を増やすなら段階3 | なし |
| 選択待ち（個体選択） | 持ち主で符号反転・BP＋レベル | 「その個体が除去された盤面の評価」で選ぶ。破壊・疲労など効果の種類は purpose が無いので区別しない | 小。purposeタグ（issue 改善1）後に再検討 |

マジック・起動のタグ別点は**段階2では評価関数に移さない**（結果が盤面計算で出ないので段階3向き）。

### 8.4 守る点

- evaluate.ts の冒頭の方針（GameView のみ）を守る。boardEval.ts は GameState を import しない。
- 相手の手札・デッキ内容は項に入れない（枚数のみ）。
- 旧 `boardStrength` は呼び出しが無い。`evaluateBoard` へ置換して消す（残すと二重の評価になる）。

### 8.5 測り方（`ai:bench` に足す）

いまの bench（scripts/ai-bench.ts:35〜）は両者が同じ `decideAiAction`（index.ts:21）を使う自己対戦で、統計だけを出す。段階2の効果は「新対旧」の勝率で見る。

1. `decideAiAction` に引数 `policy`（既定は現行の `pickBestMove`／新は `pickBestMoveV2`）を足すのではなく、**`AiPolicy = { pick(view, me, moves): AiMove | null }` を `pumpAiSync` の引数 `policies?: Partial<Record<PlayerId, AiPolicy>>` で渡す**（既定は現行。本番の呼び出しは変えない）。
2. 旧 AI は `evaluate.ts` の `pickBestMove` をそのまま残す（旧＝段階1完了時点）。新は `evaluateBoard` を使う分岐を `pickBestMoveV2`（同ファイルまたは `boardEval.ts` 経由）として足し、**動作が確かになるまで既定は旧のまま**。

### 9.2 設計の要点

| 論点 | 決め方（案） |
| :-- | :-- |
| 複製 | `structuredClone(state)`。1決断につき、決定化した基準の複製を1つ作り、候補ごとにそれをもう一度複製（0.04ms） |
| 隠し情報（決定化） | AI の呼び出し口（`decideAiAction`）は GameState を持つので、**相手の手札・デッキを見ない約束は決定化で守る**（型では守れない）。基準の複製に対し：①自分のデッキ順をシャッフル（自分のデッキの中身は自分が知っているが順は知らない）②相手の手札を「相手の公開ゾーン（場・トラッシュ・除外）に見えているカード」から枚数ぶん抽出して置き換える。見えているカードが無ければ手札を空にする（＝フラッシュで返されない前提。枚数の差は全候補に共通で、比べるときに打ち消される）③相手のデッキはシャッフル（順だけ隠す。中身の多重集合は漏れるが、1手の試行では相手のドローが結果を変えにくい）④相手のバースト（`player.burst`）は null にして `burstSet` だけ残す（伏せたカードで試行が変わらないように。⚠️ `burstSet` と `burst` は常に一致する前提（playerState.ts:64）なので、この置き換えは実装前に エンジンの該当読み取りを確かめる） |
| 試行の終わり | 手を1つ解決したら、`!battle && !pendingChoice` になるまで、**決め手を持つ側**（選択待ちなら `pendingChoice.pid`、フラッシュなら `priorityPlayer`、ブロック待ちなら防御側）を `decideAiAction(sim, pid, ∅, OLD_POLICY)` で進める。上限30手（実測では掛かった試行0）。そこで `evaluateBoard(viewFor(sim, me), me)`。上限に掛かった・エンジンが手を拒否した・例外が出た試行は**その候補の試行値なし**として捨てる |
| 前進保証ドライバ | ①上限30手 ②各手の結果が拒否なら打ち切り（`pumpAiSync` の `rejected` 集合と同じ考え）③`try/catch` で例外も打ち切り。いずれも「試行値なし」を返すだけで、本番の手の選択は旧の方針に落ちる＝止まらない。**自己応答は `pumpAiSync` を使わない**（あれは `state` の勝敗まで回し続ける。必要なのは「1つの未解決を閉じるまで」なので、`decideAiAction` の薄いループを `lookahead.ts` に持つ） |
| endTurn の扱い | 試行しない。値は**現在の局面の `evaluateBoard`**（基準値）に置く。`nextPhase`・`pass` は試行する |
| 採否のルール | 試行値が出た手のうち最大のものが、基準値より **MARGIN（置き値 +10）以上高いときだけ**それを選ぶ。そうでなければ旧の方針（`pickBestMove`）に落とす。旧を残す理由：先読みは1手のみで、「召喚してからアタック」のような複数手の組み立てを読めず、段階2で見積もりが旧に負けた前例があるため。MARGIN は bench で決める |
| どの手に使うか | 段階2と同じ手順で**手の種類ごとに足して測る**。順番（効果が出やすい順）：①選択待ちへの答え（旧は `options[0]`。候補が平均2〜数個）②アタック・ブロック・ライフ受け（試行が最も重い 1ms 前後。実際の解決結果が読める）③マジック・起動（効果の中身を読まない弱点の解消）④召喚・配置・コア（旧の点表と競合しやすいので最後） |
| 絞り方・予算 | 候補は平均2.5・最大10。測定では絞り不要（最大13ms）。それでも実機（Worker）の安全弁として、1決断の予算を **50ms**（`BS_AI_LOOKAHEAD_MS` で上書き）とし、`pruneMoves` 後の順に試し、超えたら残りの候補は試さず旧の方針の点で足す。上位 K だけ試す案は、候補数が小さい実測に対して不要（候補が増えたら K=8 を足す） |

### 9.y 段階3の後に足す評価（2026-11-20 ユーザーと相談）
- **場のカードの効果の価値**：先読みは自分の手の解決で止まるので、相手のターンに効くネクサス・スピリットの効果（ドロー・コア増・除去など）は見えない。場のカード（両者）の継続効果・誘発に、moveTags と同じ考え方で効果データから分類を付け、evaluateBoard に価値として足す（カード ID で分岐しない）。足りなければ段階4（相手のターンまで読む）
