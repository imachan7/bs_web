## 目的
担当カードの効果文を**全節**、処理順の表にする。ユーザーがこの表を読んで良し悪しを判断し、確定した表がそのままテストの期待値になる。
「迷う点だけ」ではなく、**判断が割れない節も全部**載せ、自分の読みを書く。

## アルティメットについて（ULTIMATE_PLAN の要点。必ず当てはめる）
- 「スピリット」を対象・範囲にする効果はアルティメットに当たらない。「スピリット/アルティメット」「アルティメット」と書いた効果だけ当たる（B1）。**既存カードの「相手のスピリット」はアルティメットに効かない**ことを、スピリット・マジック・ブレイヴの節でも毎回当てはめる
- アルティメットのエンジン（`field.ultimates`・召喚条件・Uトリガー）は**まだ無い**（ULTIMATE.md の段階移行 0〜8 が未着手）。アルティメットの節の実装欄は「ULTIMATE_PLAN C3 の段2」のように、確定済みの手順の段を指せばよい。器の名前を作り込まない
- 【Uトリガー】は1回の発揮ごとに段1〜6（ULTIMATE_PLAN §3）。ヒット効果の節は「段4」、ヒットしたとき／ガードされたとき／発揮後は「段5」、XU は「段6」

```
## 確かめたいこと

- **058-2** 何を・どちらに読んだか・どちらだと何が変わるか（1行）
```
- 行 id は `<cardId の末尾>-<節の番号>`（`058-1`、X は `X01-1`、CP14 は `CP14X01R-1`）。1行＝効果文の1節（見出し『…』1つ、キーワード1つ、召喚条件1つ）。「その後」「さらに」で続く文は同じ行の中に処理順として書く
- 表のセルに `|` を書かない。改行も書かない
- **読み（処理順）**：最初に「節の効果文（要約可）」を鉤括弧で。続けて、いつ（タイミング）・誰が選ぶ・何が先か（「その後」等の前後関係と、1文の複数対象は同時）・対象がいないとき（不発か、残りだけ行うか）・アルティメットに当たるか
- **根拠**：Q番号／ULTIMATE_PLAN の行／手順書の名前。どれも無い自分の判断は必ず `**読み**` と書く（ユーザーに見せる印になる）
- **実装**：既存の器なら名前と手本の効果 id（`BS20-051-e2` のように）。足りないなら「足りない部品：名前（種別）」と、組み合わせで書けない理由を一言。下の設計の原則を守る
- **テスト**：「動く：…／動かない：…」。**1節につき動く盤面と動かない盤面の両方を必ず書く**（ユーザー指示 2026-11-22）。動かない盤面は、その節で起こりうるものから選ぶ：耐性・【装甲】で受けない／対象がいない／条件・Lv 未達／コストを払えない／アルティメットには当たらない／召喚条件を満たさない、など。「正しく動く」だけの行は不可。強制で動かない盤面が本当に無いときだけ「動かない：—（強制）」

## 設計の原則（実装欄を書くとき）
1つの効果は、単純な効果の組み合わせで表す。新しい type／kind を出す前に、既存の器の組み合わせで書けないかを確かめる（「その後」＝`sequence`、絞り込み＝`filter`、「〜1体につき」＝`countCounter`、「〜することで」＝`pay`、「〜とき／なら」＝`if`、「各〜ごとに」＝`forEach`）。書けないときだけ**足りない部品1つ**（アクション・条件の軸・タイミング・組み合わせ方のどれか）を挙げる。1枚専用の複合 type は挙げない。情報は記録の枠や state の一時フィールドで運ばず、action か誘発の引数で渡す。
