# 効果のコスト（「Aすることで、Bする」）の手順

`EffectAction` には支払いを表すフィールドが10個以上ある（`costReserveToVoid` / `costDestroyOwnKeyword` /
`costExhaustFamily` / `costSkipDraw` …）。カードが来るたびにその1枚専用のフィールドを足してきたため、
**コストとは何かという一般則が無い**状態だった。この文書がその一般則を持つ。

## 1. 基本規則（2026-08-13 ユーザー確定）

> 「**A することで、B する**」は、**A と B の両方が完全に解決できる場合にだけ発揮できる、任意発揮の効果**。

ここから3つが導かれる:

1. **発揮可能かの判定に B の成立も含む。** 「コストは払えるが対象がいない」は**発揮できない**。
   「コストを払ってから対象を探して不発」は誤り。
   ただし**発動確認は出してよい**（2026-08-13 ユーザー判断）。押しても損はせず、
   「〜がないため発動しなかった」と**理由がログに出るぶん、確認が出ないより分かりやすい**
2. **A と B を同時に満たせるかを、何かを動かす前に確かめる。** 支払いも効果適用も、
   判定を通ってから行う
3. **任意発揮**。払えて対象もいる場合でも、プレイヤーは発揮しないことを選べる
   （`optional: true` の発動確認）

### 実装の形

```ts
// ① A（コスト）を払えるか  ② B（効果）が成立するか  ——両方を先に確かめる
if (!canPayCost(...) || !hasResolvableTarget(...)) {
    log(state, `${sourceName}：発揮できなかった。`)
    return
}
// ③ ここまで来たら、支払い → 効果適用の順に実行する
```

`optional: true`（発動確認）は満たさないときも出てよい（上記）。ハンドラ側が必ず
「何が無いから発動しなかったか」をログに残すこと。

### 数が足りないときは「あるだけ処理してコストも払う」（2026-09-02 ユーザー確定）

**「Aすることで、B を2つする」で B が1つしか満たせないとき**に発揮できるのか。該当は実カード2枚:

| カード | A | B | 足りない状況 |
| :-- | :-- | :-- | :-- |
| BS07-X26 剣王獣ビャク・ガロウLv2 | リザーブのコア1個をトラッシュへ | 【転召】を持たない相手のスピリット**2体**を手札に戻す | 候補が1体のとき |
| BS04-X15 カイザーアトラス皇帝Lv2 | リザーブのコア1個をボイドへ | 相手のライフのコア**2個**をリザーブへ | 相手のライフが1のとき（減らせば勝ちが決まるので実戦では問題になりにくい） |

**「あるだけ処理してコストも払う」で確定した**（＝体数は不足してよい）。
§1 の「完全に解決できる」は**コストと効果の成立**にかかる話で、**体数には及ばない**。
対案だった「2体いなければ発揮できない」は採らない。回帰テストは smoke `part178`。

成立判定のしきい値は「候補 ≥ 1」のまま（`count` とは比べない）。

## 2. 何を犠牲にするかは選ばせる（2026-08-13 ユーザー確定）

コストの対象（破壊する自分のスピリット、疲労させるスピリット等）が**2つ以上あるときはプレイヤーに選ばせる**。

`requestChoice` の既定パターン（`INTERRUPTION_POINTS.md` パターンA）に載せる。
候補1つなら即確定、0なら §1 により発揮不可。非対話（smoke）は従来どおり自動選択を残す。

**実装の形**：選ばせたら、**そのコスト軸を落とした action で入り直す**（`ctx.resolve`）。
二重に払うのを構造的に防ぐため。`exhaust` の `chooserIsTarget` と同じ「解決済みの軸を落として再入する」書き方。
再入時に渡る `targetInstanceId` が犠牲であることは、内部専用フィールド `costSacrificeChosen` で示す。

```ts
const { costDestroyOwnFamily: _paid, costSacrificeChosen: _flag, ...rest } = action
if (action.costSacrificeChosen && targetInstanceId !== undefined) {
    /* targetInstanceId を犠牲として支払う */
    ctx.resolve(rest)   // ← コスト軸が消えているので本体だけが走る
    return
}
```

2026-08-13 に4枚へ適用済み（smoke part177）:
ブリュナグオン（`costDestroyOwnKeyword`）／キャストオフ（`costDestroyOwnFamily`）／
リクラメーション（`costDestroyOwnNexus`）／秘密の花園（`costExhaustFamily`）。
リザーブや自身の上のコアを払うもの（`costReserveToVoid` 等）は、どのコアを払っても同じなので選択の対象外。

## 2.5 実装が §1・§2 に追いついていなかった分（2026-08-23 ユーザー再確認）

ユーザーの言葉で改めて確定した3点。**いずれも §1・§2 と同じ内容**だが、
実装が追いついていない箇所が残っていたのでここに記録する。

> 「することで」の効果は**任意効果**。
> 「ことで」を真ん中にして、**左と右がどちらも達成可能なときに発動可能**。
> **発動するかはプレイヤーに聞く。**

### 発動確認（optional）が付いていなかった4枚

`optional: true` が無いと `requestActivationConfirm` を通らず、**コストを払うかどうかを
決められないまま自動で払う**。カードデータは型検査の対象外なので、書き忘れても全緑をすり抜ける。

| カード | 「ことで」の節 |
| :-- | :-- |
| BS04-022 王蛇ケツァルカトル | 手札を好きな枚数破棄することで、コアを置く |
| BS04-061 戦闘獣ジャッカー | このスピリット上のコアすべてを置くことで、ネクサスを戻す |
| BS05-047 ブロンズ・ゴレム | コア1個をトラッシュに置くことで、ネクサスを戻す |
| BS08-045 勇者フェニックスペンタン | デッキの上に戻すことで、このスピリットは回復する |

**マジックには付けない**。「使用する」と決めた時点でプレイヤーが発動を選んでいるので、
二重に聞くことになる（サクリファイス／キャストオフ／リクラメーション／ユナイテッドパワー／
マインドブレイク／エリミネイションの6枚。無償化の確認＝§5 とは別の話）。

### 犠牲の選択（§2）が入っていなかった3アクション

コストがアクション名に焼き込まれている型は、§2 の「コスト軸を落として再入する」書き方が使えない。
代わりに**内部フラグ `sacrificeChosen`** で「犠牲を選び終えて再入した」ことを示す。

| アクション | 犠牲 | カード |
| :-- | :-- | :-- |
| `selfBuffByExhaustFamily` | 疲労させる1体 | 巨神機トール／紅玉の火山弾／鎧神機ヴァルハランス |
| `refreshSelfByDestroyFamily` | 破壊する1体 | 巨神機トール Lv3 |
| `refreshSelfByReturnToDeckTopName` | デッキの上に戻す1体 | 勇者フェニックスペンタン |

⚠️ **`targetInstanceId` は二重の意味を持つ**。これらは誘発（onAttack 等）からも呼ばれ、
そのとき `targetInstanceId` にはイベント対象が入る。フラグ無しでこれを犠牲と読むと誤作動する
（`refreshOne` で実際に踏んだ。part230 参照）。**`sacrificeChosen` が付いているときだけ読むこと。**

検証は smoke part231。

## 3. 現状の適合状況（2026-08-13 時点）

| アクション | コスト | §1 適合 |
| :-- | :-- | :-- |
| `refreshSelf` | `costReserveToVoid` / `costSelfCoresToVoid` | ✅ 回復済みなら払わない |
| `targetNegateByHandDiscard` | 手札破棄 | ✅ `probing` で「元々防げていた対象化」には払わない |
| `recoverSpiritFromTrash` | `costSkipDraw` | ✅ 実際に戻せたときだけ支払う |
| `protectLifeByCostThisTurn` | `costExhaustFamily` | ✅ 疲労させる候補を先に確かめる |
| `returnToHand` | `costReserveToTrash` | ✅ 戻せる相手がいなければ払わない |
| `recoverSpiritFromTrash` | `costDestroyOwnKeyword` | ✅ トラッシュに戻せるカードが無ければ払わない |
| `lifeCrush` | `costReserveToVoid` | ✅ 減らせるライフが無ければ払わない |
| `levelOverrideOpponentNexuses` | `costReserveToVoid` | ✅ 相手のネクサスが無ければ払わない |
| `summonFromHandFree` | `costDestroyOwnFamily` / `costDestroyOwnNexus` | ✅ 召喚できる手札が無ければ払わない |

**全7アクションが §1 に適合した**（2026-08-13。smoke part178。実カード6枚：ビャク・ガロウ／
ブリュナグオン／キャストオフ／リクラメーション／カイザーアトラス皇帝／皇帝アンプルール）。

`summonFromHandFree` だけは**維持コアが足りるかまでは見ない**：コストで破壊したスピリットのコアが
リザーブに戻り、支払い後に払えるようになる場合があるため（誤って発揮不可にしないための保守的な判定）。

### 発動確認の抑止は「やらない」で決着（2026-08-13）

成立しないときも `optional` の発動確認は出る。押すと何も起きずログだけが出るが、
**理由が見えるぶん確認が出ないより親切**というユーザー判断により、ここは追わない。

（もし将来やるなら、確認を出しているのは `fireStepTriggers` / `fireTrigger` という
アクション実行**前**の層なので、A と B を副作用なしで判定する述語が要る。
その述語はハンドラと**同じ候補列挙を共有できる場所**に置くこと。別実装にすると判定と本体が食い違い、
「片方だけ正しい」状態が生まれる＝`destroyExhausted` と `destroy` で実際に起きた事故と同じ轍。）

## 4. コストの代替支払い（別概念なので混ぜない）

「支払うコストを別の資源で払える」は上とは別の仕組み。**カードのコスト計算**の側にある。

| 仕組み | カード | 実装 |
| :-- | :-- | :-- |
| `summonCostHandDiscardPay` | ビクティム | 召喚コストを手札破棄で。効果文が「すべて、または一部」と書いているので**枚数はプレイヤーが選ぶ**（コア払いと併用できる） |
| `nexusCostMillPay` | 栄光の表彰台 | 配置コストをデッキ破棄で。効果文に「一部」が無いので**コア払いと併用できない**（下記） |
| `constraint: tenshoCoreSubstitute` | ダークスカルデーモン | 【転召】の対象になったとき疲労で代替 |

**代替支払いが「コア払いと併用できるか」は効果文で決まる**（2026-08-24 ユーザー確認）。
「支払うコスト**すべて、または一部**を」と書いてあれば混ぜてよい（ビクティム）。
その断りが無ければ**払う前にどちらか一方に決める**＝全額をその資源で払う（栄光の表彰台）。
実装では `RuleValidator.nexusMillPayAmount` が 0 か実効コストのどちらかしか返さず、
中間の枚数を指定した `setNexus` は検証で弾く。**置くコア（維持コア）は常にコア払い**
（「配置に支払うコスト」ではないため、どちらの型でも代替の対象外）。

## 5. 必須コスト

**【転召】は任意コストではなく召喚の必須コスト**。対象がいなければ**召喚そのものができない**
（`validateSummon` が拒否する。2026-08-13 修正）。対象になったスピリットは破壊ではなく
維持コア割れによる**消滅**なので、破壊時効果は発揮されない。詳細は SPEC.md §2「効果による召喚と【転召】」。

## 6. 「使用できる」「召喚できる」は、コストを**通常どおり払う**（2026-08-27 ユーザー確認）

効果文に「**コストを支払わずに**」と書いていない限り、コストは通常どおり必要。
「〜できる」が免除するのは**手順**（トラッシュから使える／デッキから召喚できる）であって、コストではない。

- BS10-046 龍仙公主Lv2「自分のトラッシュにある黄のマジックカード1枚を、手札にあるときと同様に使用できる」
  → **コストを払って使う**。発揮タイミングが『このスピリットのアタック時』なので、使うのは**フラッシュ効果**。
  使用後はトラッシュへ戻る
- 同じ規則は召喚側で先に確定している（`summonFromTrashFree.payCost`＝BS07 常闇の聖堂。2026-08-24）
- 対比：BS10-X05 堕天神龍ヴィーナ・ルシファーは「**コストを支払わずに**即時に発揮する」と明示しているので払わない

## 5. 「コストを支払わずに使用できる」は、使用時に**払う道も残す**（2026-08-15 ユーザー確認）

マジックの無償化（`kind:"magicFreeGrant"`）は「使用**できる**」なので、
**無償化を持つカードすべてで、使用のたびに聞く**。あえてコストを払う選択を残すのは、
無償化の枠が1枚きりのカード（大天使イスフィール＝「マジックカード**1枚**を」）で
**枠を温存**できるようにするため。

| 論点 | 確定した規則 |
| :-- | :-- |
| 聞く範囲 | 無償化を持つ**5枚すべて**（ミカファール／バロッサ／イスフィール／アンブロシウス） |
| 選択肢 | 2択（コストを支払わずに使用する／コストを支払って使用する） |
| 聞かない場合 | **払える見込みがないとき**（払う道が無いので聞いても意味がない）。リザーブだけで見る簡略化 |
| 枠の消費 | 払って使ったときは **1枚きりの枠を消費しない**（使っていないので残る） |
| 「もう1度だけ発揮できる」 | これも**任意**。1回目が解決しきってから聞く（『効果発揮後』なので順序が決まっている）。発揮しなければ枠は残る |

**非対話（テスト・自動解決）では従来どおり**自動で無償・自動で2回発揮する。
実装は `effectiveCost` の `ignoreFreeGrant` 引数と `GameState.magicFreeDeclined`。
