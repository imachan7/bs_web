# 実行時カバレッジの作り替え（2026-10-15 設計。ユーザー合意）

## 1. いまの作りと、何がまずいか

`scripts/coverage-effects.ts`（2182行）は、HEAD の使い捨て worktree に **正規表現で計測コードを差し込み**（`patch()` 133か所、うち継続効果の計測点76）、smoke を1回走らせて、通った効果エントリを数える。

- **ソースの書き換えで壊れる**：差し込み先は「この文字列が1か所だけある」で決めている。関数を移す・1行直すだけで差し込み先が消える（2026-10-15 に #268 で2か所壊れ、part160 が落ちた）。分割を進めるほど壊れる
- **計測点が無いことが分からない**：新しい kind を足しても、差し込みを足さなければ「未計測」の一覧に出るだけで、落ちない（BS15 の時点で19種86件が未計測のまま）
- **ブレイヴ経由で動いていても「未実行」と出る**：差し込みが `self.cardId` を見る形のため（CLAUDE.md の既知の限界）
- worktree を作るので遅い

## 2. 新しい作り

**計測点を、ソースに1行の呼び出しとして書く。** 差し込みはやめる。

```ts
// shared/coverage.ts（サーバーとクライアントの両方から呼ばれる。ブラウザでは何もしない）
export function noteEffect<K extends EffectDef["kind"]>(effect: Extract<EffectDef, { kind: K }>, kind: K): void
```

- 呼ぶ場所：その kind の効果が**発揮すると決まった時点**（条件・レベル・ターン1回などを通った後）。ブレイヴ経由でも、発揮する所で呼ぶので数えられる
- **2つ目の引数に kind の文字列を書く**。型の上で `effect` がその kind に絞り込まれていないと tsc が落ちるので、書く場所を間違えにくい。数える側（静的検査）は、この文字列で「どの kind に計測点があるか」を拾う
- action（`type`）は従来どおり `resolveAction` の入口1か所で数える（`noteAction`）。どの効果から来たかは、効果側の `noteEffect` で分かる
- 記録：環境変数 `BS_COVERAGE_OUT` があるときだけ、`effect.id` を Set に入れ、プロセス終了時に1回書き出す。無ければ何もしない（ふだんの smoke と本番に影響しない）

## 3. 2つの検査

| 検査 | 中身 | どこで回す |
| :-- | :-- | :-- |
| `validate:coverage-points`（静的・速い） | EffectDef の全 kind（types から TypeScript の API で読む）と、ソース中の `noteEffect(…, "kind")` の kind を突き合わせ、**計測点の無い kind があれば落とす**。いま無いものはベースラインに載せ、増えたら落とす（validate:gaps と同じ形） | 定型と CI |
| `coverage:effects`（実行時・遅い） | `BS_COVERAGE_OUT` を付けて smoke を1回走らせ、カードデータの全エントリと突き合わせて「計測点はあるのに一度も発火していない」エントリを出す。worktree は作らない | 弾の取り込みの後（従来どおり定型には入れない） |

## 4. どう壊れうるか・機械的に回せるか（method-design-first）

- **呼ぶ場所が早すぎる**（条件を見る前に呼ぶ）と、発火していないのに「通った」と数える。→ 規則「条件をすべて通った後に書く」を WHERE_TO_ADD に置く。移行のときは今の差し込み先（条件の後に置いてある）をそのまま写す
- **kind を足したのに計測点を書き忘れる** → 静的検査が落ちる（いまは落ちない）
- **関数を移す・分割する** → 呼び出しはコードと一緒に動くので壊れない（`split-file.ts` で移しても残る）
- **effect をスプレッドで写す** → `id` はフィールドなので残る
- 繰り返す作業（kind を足す）は「`noteEffect` を1行書く」だけで、判断が要らない

## 5. 移行の手順

1. `shared/coverage.ts` と静的検査を作る
2. いまの継続効果の計測点76か所を、`patch()` の差し込み先から読み取って `noteEffect` の呼び出しに置き換える（差し込み先はスクリプトに書いてあるので機械的に写せる）。ACTION_BEARING_KINDS（triggered・magic・step・fieldEvent・battleWon・activated）は、発火する所（`fireTrigger` の各エントリの解決・`fireFieldEventTriggers`・ステップ・起動・マジック）に書く
3. 実行時の計測を新しい作りで1回回し、旧スクリプトの結果と「通ったエントリ」が一致することを確かめる（一致しない所は、どちらかの計測点の置き場が違う）
4. 旧スクリプトの差し込み部分と part160（差し込み先の健全性検査）を消す。CLAUDE.md の「ブレイヴ経由の既知の限界」の段落を消す
5. 計測点の無い kind（BS15 時点で19種）に `noteEffect` を足し、ベースラインを縮める
