# バトスピ Wiki「わかりづらいルール」の調査（2026-09-08）

一次資料: <https://batspi.com/index.php?わかりづらいルール>（9つの子ページに分かれている）。
**公式ルールブックに書かれていない細かい裁定がまとまっている。**
このリポジトリは「ゲームの手順」の記述が薄く、推測で実装すると
[間違ったまま smoke が全緑になる](../../CLAUDE.md)ため、突き合わせ先としてここに写す。

[PROCEDURES_AUDIT.md](./PROCEDURES_AUDIT.md) §2 の索引と一緒に見る。
**「未確認」の行は、その規則に関わる実装に手を入れるときに必ず調べること。**

## 1. 破壊について

| 規則（原文の要約） | 状態 |
| :-- | :-- |
| 破壊されたカードは**破壊待機状態**になり、その破壊で誘発した効果がすべて解決されるまでフィールドに残る。その後トラッシュに置かれる | ✅ [TIMING_CHART.md](./TIMING_CHART.md) §1.5 |
| 破壊待機状態のカードは、フィールドに存在し、乗っているコアもそのまま。破壊時に誘発した効果の**対象になる** | ✅ |
| 破壊待機状態のカードは**疲労も回復もできない** | ❓ `removal.ts` のコメントには同趣旨の記述がある |
| 破壊待機状態のカードは**ブレイヴの合体ができない** | ❓ 未確認 |
| **破壊待機状態のスピリットのシンボルは、破壊時に発揮される効果の軽減に使える**（消滅・バウンスと違う点） | ✅ `countSymbols` は `pendingBounce` だけを除外している |
| **解決の途中で破壊状態が解除されると、以降の「破壊されたとき」の効果は処理されない** | ✅ 2026-09-08 に実装（下記） |

### ⚠️ 「解決中に破壊状態が解除されたら以降は処理しない」について

2026-09-08 に「フィールドに残る／戻る」を **`commitPendingDestruction`（誘発をすべて解決したあと）** で
適用するように直した。この形だと**破壊状態の解除が必ず最後**になるので、
「解除されたあとの破壊誘発を飛ばす」場面が生じない。

Wiki の記述は「**『フィールドに残る』自体も破壊で誘発した効果のひとつ**で、
ターンプレイヤーが決めた解決順の途中で解決されうる」という前提に読める。
そうだとすると、残る効果を先に解決した場合、**まだ解決していない破壊誘発は飛ぶ**ことになる。

**2026-09-08 に実装した。** 破壊で誘発するものは1つの列に並べ、ターンプレイヤーが1つずつ選ぶ。
「フィールドに残る／戻る」もその列の1項目で、解決した時点で破壊が無かったことになり、
列の残りは空振りする。詳細は [TIMING_CHART.md](./TIMING_CHART.md)、テストは `scripts/smoke/part302.ts`。

## 2. 消滅について

| 規則 | 状態 |
| :-- | :-- |
| 消滅＝「乗っているコアが最低維持コア未満になったこと」。かつて「Lv0として破壊」と呼ばれていたもの | ✅ `cause: "deplete"` |
| **消滅は破壊ではないので、破壊に関する効果は一切発揮されない。** 代わりに消滅時効果が誘発する | ❓ `destroySpirit` は `cause === "destroy"` のときだけ `onDestroy` を出す |
| **消滅したカードは、消滅に関係ない効果が無効になり、そのシンボルで軽減することもできなくなる** | ✅ 軽減は 2026-09-16 に修正（`pendingVanish`。smoke part329）。「消滅に関係ない効果が無効」は未確認 |
| 消滅してもまだコアが置かれている場合、そのコアはリザーブへ置かれる。**この移動は効果ではないので「コアが0個になった」ことにはならない** | ❓ 未確認。「コアが0個になったとき」を条件にする効果に影響する |

### ✅ 解消済み（2026-09-16）：消滅待機中のシンボルが軽減に数えられていた

`destroySpirit` は破壊でも消滅でも同じ `CardInstance.pendingDestruction` を立てるため、
`countSymbols` は**この2つを区別できない**。実測（2026-09-08）:

| 状態 | いまの軽減の数 | Wiki の正解 |
| :-- | :-- | :-- |
| 通常 | 1 | 1 |
| 破壊待機 | 1 | **1**（破壊待機のシンボルは軽減に使える）✅ |
| バウンス待機 | 0 | **0**（`pendingBounce` で除外済み）✅ |
| **消滅待機** | **1** | **0**（消滅したカードのシンボルは軽減に使えない）❌ |

直すなら、消滅のときだけ別の印を立てて `countSymbols` で除外する。
**影響は「維持コア割れで消滅した直後に、その消滅で誘発した効果でカードを召喚する」場面に限られる**ので、
実戦で踏む頻度は低い。ただし直し方は小さい。

## 3. バウンスについて

| 規則 | 状態 |
| :-- | :-- |
| 2020年5月のルール改定で、バウンスにも**待機状態**が入った | ✅ `pendingBounce` |
| 待機状態の間は「フィールドを離れるとき」「手札/デッキ/手元に戻るとき」の効果**だけ**が発揮できる。フィールドに残る効果があれば残り、なければ指定の場所へ移る。**行き先によらず共通**（2026-09-23 ユーザー確認） | ❓ 実装が行き先ごとに揃っているかは未確認 |
| **バウンス待機状態のスピリットのシンボルは軽減に使えない**（破壊待機と違う点） | ✅ `countSymbols` が `pendingBounce` を除外している |

## 4. 効果の分類について

| 規則 | 状態 |
| :-- | :-- |
| **常在型効果**（【装甲】等。`『　』`でタイミングが指定されていないもの）は**解決順の最優先**で、他の効果より先に解決される | ⚠️ 未確認。同時発揮の解決順はターンプレイヤーが決める実装だが、「常在型が必ず先」を明示的に守っているかは調べていない |
| 複数の効果が同時発揮するときは**ターンプレイヤーが解決順を決める** | ✅ [TIMING_CHART.md](./TIMING_CHART.md) |
| 「さらに」＝同時／「その後」＝前を先に解決／「効果発揮後」＝派生を完全解決してから次へ | ✅ [CONJUNCTION.md](./CONJUNCTION.md) の早見表と一致 |
| ひとつの効果の解決中に誘発した効果を**派生効果**と呼び、その連なりを**解決軸**と呼ぶ。**解決軸が完全に終わるまで、消滅・破壊状態のカードはトラッシュに置かれない** | ✅ 破壊待機の実装がこの形 |
| **【合体中】効果は合体が解除されると即座に効力を失う。ただし解決済みの「このターンの間」等の持続効果は無効にならない**（2018-04-21 改定） | ❓ 未確認。[BRAVE.md](./BRAVE.md) に該当の記述があるか要確認 |

---

### ✅ 解消済み（2026-09-16）：「ターンに1回」がコスト不発でも消費されていた

`triggered` / `fieldEvent` は条件に合致した時点で使用済みにしていた。**払えなければ発揮していないので消費しない。**
コスト不発の箇所で `state.effectFizzled` を立て、解決後に巻き戻す。「〜できる」の確認を断ったときは
`PendingChoice.revertTriggered` で戻す（smoke part328）。
⚠️ 巻き戻すのは**コストを払えなかった**ときと**断った**ときだけ。「対象がいなくて何も起きなかった」は対象外
（それを発揮と見なすかはルール上はっきりしないため、変えていない）。

## 5. カードのコスト及びその支払いについて

| 規則 | 状態 |
| :-- | :-- |
| 支払いは提示した時点で決定。順序は **①総コスト決定 → ②軽減シンボル適用 → ③余分コスト適用 → ④支払い** | ⚠️ 下記 |
| **余分コスト（追加コスト）は軽減の「あと」に乗る。** 軽減で0にしたコストにも追加コストが発生しうる | ✅ 2026-09-16 確認。`effectiveCost` は「軽減 → 0で下げ止め → 余分コスト加算」の順。`costMod` の `add` は全件「〜コスト余分に支払う」 |
| 一度軽減シンボルを適用したあと、その数を追加コストで軽減し直すことはできない | ❓ 未確認 |
| **「コストを◯にする」は①総コストを決めるだけで、そこからさらに軽減できる** | ✅ 2026-09-16 ユーザー確定・修正（以前は置換すると軽減を一切適用しなかった。対象13枚。smoke part130/131/138） |
| コストを**固定値にする**効果が複数あるときは、**後から発揮した効果が優先** | ⚠️ 実装は「**最も小さい値を採る**」（`shared/cost.ts` のコメントに「決定的にするため。現状そのカードは無い」とある）。**該当カードが出たら直すこと**（2026-09-16 ユーザー判断：いまは直さない） |
| 「**本来のコスト**」と明記した効果は、軽減後ではなく**カード記載の原文コスト**を参照する | ✅ BS13-003 カメレオプスで実装済み（BS13_PLAN §6 の器C） |

## 5.1 シンボルの固定

| 規則 | 状態 |
| :-- | :-- |
| 「シンボルを◯つにする」「◯のシンボル◯つにする」は**固定**（公式のルール改定で「◯つに固定する」へ表記変更。裁定の変更はない）。**固定を受けたシンボルは、追加・失う効果やブレイヴの合体で増減しない** | ✅ 2026-09-25 ユーザー確認・修正（以前は追加を固定値に足し、失うを固定値から引いていた。smoke part383）。固定が複数重なるときは期間つき＞継続の順で1つだけ見ており、発揮順は見ていない |
| 「**Lv◯BPを◯として扱う**」は今の BP ではなく Lv の BP を置き換える。**ブレイヴの合体時BP+ は含めて置き換わる**（あとから合体しても足さない）。**効果による BP+ とオーラは、掛かった前後を問わず上に乗る**（先に+3000されていても 2000＋3000＝5000） | ✅ 2026-09-25 ユーザー確認（公式 Q3630・Q3632・Q18859）・修正。ベトール・サンダ・バードは BP+ を無視し、ルナアーク・カグヤと X011 はブレイヴ分を足していた（smoke part386）。継続の書き換え（X011・百地ダイル）も同じ扱い |
| Lv を指定しない「BP を◯にする」は、それより**前**の BP+ を消し、**後**の BP+ は乗る（BP1000にした後の+3000で4000） | ✅ 2026-09-25 ユーザー確認。**該当カードは今は無い**ので、掛かった順を覚える仕組みは未実装。出たら期間つき効果の一覧の記録順で計算する |

## 6. その他のルール解説

| 規則 | 状態 |
| :-- | :-- |
| カードの色は**枠の色だけ**で決まる。シンボルだけ追加される効果では色は追加されない | ❓ |
| **「色を無いものとして扱う」効果では、元の色もシンボルも失われる** | ✅ BS13 紫バッチで実装（BS13_PLAN §1 #10。`countSymbols` が該当個体を軽減からまるごと飛ばす） |
| 究極シンボル・神シンボルは**色を持つものとして扱わない** | ❓ 未実装領域（アルティメット・神） |
| 効果の記述を持たないスピリットに、バースト／アクセル／【合体中】を持つブレイヴを合体させると、その合体スピリットは**記述を持つもの**になる | ❓ バニラ判定（`isVanillaCard`）に関わる。未確認 |
| 合体スピリットは2枚1組で1体と数えるが、**合体ブレイヴはフィールドにあるカードとしても扱う**。【装甲】等の耐性は**共有**される | ✅ [BRAVE.md](./BRAVE.md) §12 と一致 |
| スピリットはブレイヴの色を**加えた**色になるが、**ブレイヴ自身はブレイヴの色のまま** | ✅ `instColors` の `braveComposite` と一致 |
| デッキの破棄は**1枚ずつ**確認する（「デッキから破棄されたとき」を拾うため） | ❓ `onMilledFromDeck` があるので形はある。まとめ処理していないか要確認 |
| **手元**のカードは手札と同様に使用宣言できるが、手札ではないので手札破壊・参照の対象外。バーストはセットできない。フィールドにあるカードでもない | ❓ `tegamoto` の実装と要突き合わせ |
| **スピリット破壊時のコア移動やバウンス時のコア移動は「取り除く」に該当しない** | ✅ **2026-09-09 ユーザー確認**。離場に伴うコア移動は「コアを取り除けない」に引っかからない。止めるのは明示的な除去効果とコストの支払いだけ（緑の器AC＝BS13-065 Lv2 / X03 Lv3） |
| **破壊されたスピリットのコアの行き先を変える効果**（ガイ・アスラ＝ボイド、赤き前方後円墳・古龍の縄張り＝トラッシュ、ヘッジボルグ＝ボイド）は**【装甲】等の耐性では防げない** | ✅ **2026-09-26 ユーザー確認**。スピリットを対象にせず処理の行き先を変える効果で、コアが移るのはスピリットが場を離れるとき。実装も耐性を見ていない |
| **「疲労する」と「疲労状態になる」は別。** 召喚時に疲労状態でフィールドに出ても「疲労した」ことにはならないので、『疲労時』効果は発揮しない | ✅ **2026-09-09 ユーザー確認**。`ownSpiritExhausted` を誘発させない。**さらに「疲労状態で召喚する」はルールに干渉する効果なので【装甲】等の耐性では防げない**（緑の器AB＝BS13-065 / X03） |
| 「効果で手札が増える」に**ドローステップのドローは含まない**。「ドロー+1」「ドローステップ追加」も非該当だが、「ドローの代わりに手札に加える」は該当 | ✅ **2026-09-09 ユーザー確認**。ドローステップの枚数+2 では『効果で手札が増えたとき』は誘発しない（黄の器Y＝BS13-063 Lv2） |
| **カードの効果はルールに勝つ。** 後出しのカードの記述が先出しより優先 | ❓ 一般則 |
| 公開情報＝デッキ枚数・リザーブ・トラッシュ・手札枚数・フィールド・ライフ・オープンされたカード／非公開情報＝デッキ内容・手札内容・裏向きバースト・【分身】の内容・【毒刃】の下置き | ❓ `viewFor`（GameView）と要突き合わせ。**AIに相手の手札を覗かせない仕組み**（[AI_OPPONENT.md](./AI_OPPONENT.md)）と同じ話 |
