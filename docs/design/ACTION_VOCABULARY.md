# 単純なアクションの一覧

器の統合（REFACTOR_PLAN.md §2 の M1〜M6）の前提。
2026-09-23 にユーザーと確定した。件数は `npx tsx scripts/count-rule-terms.ts --examples` で出る。

## 1. 分け方の基準

- **別のアクションにするのは、ルール上の処理が違うときだけ**（待機状態の種類、ドロー不能での敗北など）
- **片方にだけ反応するカードがあっても、アクションは分けない。** 「〜されたとき」の誘発と「〜されない」の耐性は、
  アクションの軸（`from`・`to`・`cause`）の値を条件として読む
  （REFACTOR_PLAN §2.1 の当初案「片方にだけ反応するなら分ける」を置き換えた。2026-09-23 ユーザー決定）
- すべてのアクションは同じ軸を持つ：対象（陣営・`filter`・体数／すべて・選ぶ人）、量（数値か `EffectCounter`）、期間、行き先

## 2. フィールドを離れる手順（待機状態は3種類）

| 手順 | 起こる原因 | 待機中に受け付けるもの | 待機が明けたら |
| :-- | :-- | :-- | :-- |
| 破壊 | 破壊する効果、BP比較 | 破壊で誘発した効果（シンボルは軽減に使える） | トラッシュへ（TIMING_CHART.md §1.5） |
| 消滅 | コアが最低維持コア未満になった（**効果のアクションではない**） | 消滅時の効果だけ。破壊に関する効果は発揮されず、シンボルも軽減に使えない | トラッシュへ。残ったコアはリザーブへ（効果ではないので「コアが0個になった」ことにはならない） |
| バウンス | 戻すアクション | 「フィールドを離れるとき」「手札/デッキ/手元に戻るとき」の効果だけ（シンボルは軽減に使えない） | フィールドに残る効果があれば残り、なければ `to` の場所へ |

**バウンス待機は行き先（手札・デッキの上・デッキの下・手元）によらず共通**（2026-09-23 ユーザー確認）。

## 3. アクション

| 分類 | アクション | 軸 | 反応を軸で書く例 |
| :-- | :-- | :-- | :-- |
| ゾーン移動 | 召喚 | `from`（手札／トラッシュ／デッキ…）、コストの有無 | 召喚時、「召喚できない」 |
| ゾーン移動 | 配置 | `from` | 配置時 |
| ゾーン移動 | 破壊 | 対象 | 破壊時、「破壊されない」 |
| ゾーン移動 | 戻す | `to`：手札／デッキの上／デッキの下／手元 | 「手札に戻ったとき」＝`to: hand`、「手札に戻らない」＝`to: hand` の耐性 |
| ゾーン移動 | トラッシュに置く（破棄） | `from`：手札／デッキ／手元（**フィールドは入れない**＝破壊か消滅） | 「手札から破棄されたとき」＝`from: hand`、「デッキは破棄されない」＝`from: deck` の耐性 |
| ゾーン移動 | ドロー | 枚数 | 「ドローしたとき」。デッキが無いと敗北する点が「手札に加える」と違う |
| ゾーン移動 | 手札に加える | `from`：オープンしたカード／トラッシュ… | |
| ゾーン移動 | オープン | `from`、枚数 | |
| ゾーン移動 | 手元に置く | `from`：手札／デッキ／トラッシュ（フィールドからは「戻す」） | |
| ゾーン移動 | バーストのセット | | 「バーストをセットしたとき」 |
| ゾーン移動 | 合体／分離 | | 合体時、「合体できない」 |
| コア移動 | コアを置く | `from`：ボイド／リザーブ…、`to`：スピリット／リザーブ／**ライフ** | 「ライフにコアを置けない」＝`to: life` の耐性。ライフを増やすのもこれ |
| コア移動 | コアを取り除く | `to`：リザーブ／トラッシュ／**ボイド** | 「取り除くことができない」はボイド行きも止める |
| 状態変化 | 疲労 | | 「疲労したとき」 |
| 状態変化 | 回復 | `cause`：効果／リフレッシュステップ | 「効果で回復した」＝`cause: effect`（BS14-085） |
| 数値変更 | ライフを減らす | `cause`：アタック／効果、誰によって | 「ライフが減ったとき」、「減らされない」 |
| 数値変更 | BP・シンボル・コストの変更 | 期間 | （反応するカードは無い。BP を下げる効果はカードプールに0枚） |
| カードの使用 | マジックの使用 | `from`：手札／トラッシュ／手元、コストの有無 | 使用の手続きは共通（magic/cast.ts）。マジックミラーは「直前のマジックを使う」 |
| 効果 | 効果を発揮させる | 対象の効果 | 選んだカードの誘発効果をその場で発揮させる（`borrow*`） |

**アクションにしないもの**：消滅（§2 の手順）、アタック・ブロック・バトル（ステップの進行）。

**期間つきの継続効果**（「このターンの間〜できない／〜として扱う」。既存の `grant*`・`mark*`・`ban*`・`lend*` など）は、
1つの器「継続効果を期間つきで置く」にまとめ、**対象・内容・期間**の3つで書く（2026-09-23 ユーザー決定）。
対象はスピリット・ネクサス・カードのほかに**プレイヤー**も取る（「相手は〜できない」）。
内容は、既存の `EffectDef` の継続効果（`constraint`・`turnConstraints` など）と同じ語彙を使う。

- **期間**：`バトル`／`ターン`／`次の〇〇ステップまで`（そのステップの開始で切れる）／`次の〇〇ステップの間`（そのステップの間だけ効く。BS11-055・BS12-047）／
  `発生源が〇〇の間`（BS02-042 スクルディア「このスピリットが疲労状態で自分のフィールドにいる間」）／`〇〇ステップの間`（毎回。BS13-048）／`永続`
- **内容に足すもの**：アタック時とブロック時の効果の付け替え、バトルの比較基準の切り替え（BP→レベル・コア数・コストを1つの内容＋パラメータで）、
  ブロックに追加コストを要求、シンボルを失う・上書き
- **「として扱う」（上書き）**：`として扱う { 種別, コスト, 系統, Lvごとのコア・BP, 効果を失うか }`。ネクサスをスピリットとして扱う3枚
  （BS03-147・BS09-082＝ターン、BS13-048＝アタックステップの間）は、この内容で期間だけが違う。
  実装は「同じ個体のままスピリットの配列へ移す」方式を残し、移す／戻すは器の期間の始まりと終わりの1か所で行う
  （いまの `asSpiritThisTurn`・`asSpiritAttackStepScoped`・`braveStatsAsContinuous` を1つにまとめる）
- **「としても扱う」（追加）**：色やコストを足す効果（約30枚）は上書きとは別の内容にする
- **器に入れないもの**：`lend*`（マジックを仮想発生源として場に置く土台。今のまま残す）、`borrow*`（→「効果を発揮させる」）

## 3.1 組み合わせ方

| 組み合わせ方 | 意味 |
| :-- | :-- |
| `sequence` | 「その後」＝前を解決してから次 |
| `pay { cost, then }` | 「〜することで〜する」。両方が完全に解決できるときだけ発揮（COST_MODEL.md §1） |
| `if { cond, then }` | 「〜とき／〜なら」。`cond` は見るものが3種類：`last`＝直前のアクションの結果（P071「破棄したカードがバーストなら」）、`state`＝いまの盤面（BS14-X03「コアが合計8個以上のとき」。語彙は既存の条件を使う）、`event`＝誘発のきっかけの出来事（BS16-018「このバースト発動時に紫のスピリットが破壊されていたら」） |
| `forEach` | 「各〇〇ごとに1回」（重装甲の色ごと、コストごと） |
| `countCounter` | 「〜1体につき」＝量を `EffectCounter` で数える |
| `choose` | 「または」 |

（当初の `ifLast` は `if` の `cond: { last }` になった。2026-09-23 ユーザー決定）

## 4. 確認して決めた規則

- **回復**は、フィールドにいる疲労状態のスピリットが回復状態になることだけを指す。
  破壊状態や手札から回復状態でフィールドに出る（戻る）のは回復ではない（星空の冠の裁定。2026-09-23 ユーザー提示）
- 効果による回復とリフレッシュステップの回復は同じ「回復」で、`cause` で区別する（BS14-085・星空の冠は `cause: effect` だけに反応する）
- 「〜1体につき」の量は `countCounter`（量＝`(count ?? 1) × 値`、`countMax` で上限）か `amountCounter`（量＝`amount × 値`）で書き、`*Per` のような専用 type は作らない。計算は `server/src/logic/counted.ts` の1か所（対象に依存する数え方もここ）。2026-09-24
- 「この効果で消滅したスピリット1体につき」（BS10-X02）は、直前の結果を数える形（`if` の `last`／カウンタ）で読む
- 破壊・戻すなどの対象は、陣営を軸 `side`（相手＝既定／`own`／`both`）で指定する。「自分のスピリット1体を破壊することで」は `side: "own"` の破壊（2026-09-24 ユーザー確認）
- 「（相手の）スピリットのコアN個を置く」は**複数のスピリットから合計N個**を1個ずつ選ぶ（コアシュートと同じ。2026-09-24 ユーザー確認）。
  「スピリット1体のコア」と書いてあるときだけ1体から取る
