これを見て「何を新しく作るか」を決める。**まとめた後は、ルールの段 14、カードの効果の部品 69、既存の器で書けそうなもの 24。**
（「使う節」は行 id の延べ数のおおよそ。同じ節が複数の候補に出るので、正確な数ではなく順位の目安。）

## 決めること

1. **出来事の主語は「別名を作る」か「引数で絞る」か。** 各 PLAN は「流用せず名前で分ける」（アルティメットの召喚・アタック・疲労・回復・消滅・ブロックされた・破壊後・ライフ減少で約15個の別名）。1つの出来事に `subjectKinds` を足せば、既存のスピリット版は無変更。原則1は後者、各 PLAN の読みは前者。
2. **`cause`（由来・原因）を出来事の引数にまとめるか。** 召喚の由来（招雷・オンステージ・トリガーカウンター）・疲労の由来（【強襲】）・消滅／破壊の原因・回復の由来が、別々の候補として約15節に出る。まとめれば原則3（引数で運ぶ）に沿う。
3. **期間つきの誘発の登録 `registerScoped`（約40節）を作るか、`TimedContent` に誘発を載せるか。** 「このアタックでブロックされたとき」「このバトルでBP比較して〜だけを破壊したとき」「バトル終了時」「次にアタックする1体」が全部これ。最大の部品なので、先に形を決める。
4. **相手のUトリガーで置かれた札の誘発 `onPlacedByUTrigger` を、`onMilledFromDeck` に足すか別名にするか。** C2 でUトリガーはデッキ破棄の出来事を出さない。デッキの中の札が誘発を持つ新しい種類になる（約11節）。
5. **「ヒットしたとき」のタイミングの前の版が要るか（BS26b:X05-3）。** C12 の派生はタイミングの後。その間のマジックを止めたい札に間に合わない。タイミングの前の誘発を1つ足すか、X05-3 はその間の割り込みで書くか。
6. **手札・トラッシュの札が出来事を待つ `handOrTrashTrigger` を、出来事ごとの別 kind（既存の `trashReturnOn…` `freeSummonFromHandOn…`）に足し続けるか、1つにまとめるか。** 原則1の数字（328種中180種が1枚）と同じ向きの増え方になる。
7. **コアの床 `coreFloor`：既存の `coreFloorByCost`・`coreFloorWhileBlockingKeyword`・`coreFloorOwnNamedByOpponent`・`coresProtected` と、今回の個体付き・範囲付きの床（約7節）を1つにまとめるか。** まとめない場合は5つ目の兄弟が増える。
8. **`budget`（コスト合計）を BP 合計にも広げるか、`sumBp` を別に足すか。** U抜刀・BP 合計 N までの選択の2か所。
9. **分身の積層（BS25g:023-1）・色が異なる札を1枚ずつ（BS30r:040-1）など、1枚専用になりそうな部品を作るか、効果を簡略化して `card-notes.json` 行きにするか。** 原則1に反する。
10. **【オンステージ】【マイユニット】の「アタックのかわりに使う」枠と `arrangeSpirit`（並べる）は、アルティメットの時代のカードか。** 17節ぶんを含むが、アルティメットの段階移行とは独立で、先に作る必要は無い。
