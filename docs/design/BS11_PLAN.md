## 0. この弾の性格

**BS10 でブレイヴを入れた続き**で、ブレイヴを「壊す・剥がす・止める」側のカードが揃っている。
新しいキーワードは**1つも無い**（【合体中】は BS10 で `whileCombined` として実装済み）。
新機構は次の2系統に集中している:

1. **リフレッシュステップの制限**（3枚）— これまで無かった層
2. **ブレイヴへの干渉**（10枚以上）— 分離・破壊・合体の禁止・フラッシュ合体

残りは既存の器で書ける（下の §4）。

## 1. 確定した解釈（2026-09-02 ユーザー確認）

| # | 論点 | 決着 |
| :-- | :-- | :-- |
| 1 | BS11-X04「合体していないスピリットは1体しか回復できない」の選択者 | **スピリットの持ち主**。回復は各自のリフレッシュステップで起きるので、そのステップのプレイヤーが選ぶ。**リフレッシュステップに中断点を新設する** |
| 2 | BS11-015 / BS11-034「分離するときのコアの移動は相手が行う」 | **「場を離れるとき」と同じ手順**（BRAVE.md §6.3）。`pendingBraveKeeps` に乗せ、**ブレイヴの持ち主に**「残すか・どのコアを置くか」を聞く |
| 3 | BS11-014 / BS11-016「ブレイヴ1つを破壊する」 | **ブレイヴだけがトラッシュへ**。ホストは無傷で場に残る。合体中のブレイヴはコア0なので戻るコアは無い。『破壊時』はブレイヴ側のものだけ発火する |
| 4 | BS11-078 ブレイヴフラッシュ「フラッシュタイミングで合体させる」 | **効果専用の合体アクションを新設する**。メインステップの任意合体（`GameAction combineBrave`）は触らない。「ブロック宣言後は使えない」はこのマジック固有の制限として書く |

## 2. ⚠️ 実装前に決めること（推測で書かない）

### 2.1 リフレッシュステップの制限（新設。BS11-X04 / BS11-055）

| カード | 効果文 | 効くもの |
| :-- | :-- | :-- |
| BS11-X04 宝瓶神機アクア・エリシオン | 『お互いのリフレッシュステップ』**合体していないスピリットは1体しか回復できない**。さらに、**ネクサスすべては回復できない** | 両者 |
| BS11-X04（【合体中】Lv3） | 『相手のリフレッシュステップ』**相手の合体スピリットすべては回復できない** | 相手のみ |
| BS11-055 ジャノメ・シールダー | 指定したスピリットは、**次の**『相手のリフレッシュステップ』で回復できない | 1回限り |

現状のリフレッシュステップ（`PhaseManager.ts`）は「全部回復させる」ループで、
例外は2つだけ（`noRefresh` 制約と、スクルディアの `noRefreshTargetInstanceId`）。

**「1体しか回復できない」は、どれを回復させるかプレイヤーが選ぶ**ことになるので、
**リフレッシュステップに中断点が要る**（ターン開始処理は `turnStartResumeStep` で
途中から再開できるので、層としては足りている）。**選ぶのはそのステップのプレイヤー**（§1 の1）。

### 2.2 ブレイヴへの干渉（BS10 で入れたエンジンの上に足す）

| # | 効果文 | 該当 | 今あるもの |
| :-- | :-- | :-- | :-- |
| a | 相手の合体スピリット**1体を分離させる**。ただし**分離するときのコアの移動は相手が行う** | BS11-015 / BS11-034 | `detachBrave`（効果による分離。コア不要） |
| b | 相手の合体スピリットの**ブレイヴ1つを破壊する** | BS11-014 / BS11-016 | 無い（ブレイヴだけを破壊する経路） |
| c | **フラッシュタイミングで合体させる**（ブロック宣言後は不可） | BS11-078 ブレイヴフラッシュ | `combineBrave` は**メインステップ限定**（§6.4） |
| d | 相手は、**ブレイヴをスピリット状態にできない** | BS11-X02 Lv3 | 無い |
| e | 手札のブレイヴカード1枚を、**このスピリットに直接合体するように召喚できる**（効果から） | BS11-020 | 手札からのダイレクトブレイヴ召喚はある（`summon.braveTargetInstanceId`） |
| f | 相手のスピリットが**合体したとき**、その合体スピリットは疲労する | BS11-064 Lv2 | 合体を誘発の起点にする仕組みが無い |
| g | 相手の**合体スピリット**を対象にする指定（アタック不可・指定アタック） | BS11-030 / BS11-063 / BS11-X02 | `instIsCombined` はある |

**a は今回（2026-09-02）入れた `pendingBraveKeeps` の流れに乗る**：
「残すか・どこからコアを置くか」を**相手（＝ブレイヴの持ち主）に聞く**形。
`PendingChoice.braveKeep` の `pid` を持ち主にすれば届く（§1 の2 で確定）。

## 3. cardId の注意

Wiki の一覧に **`X007`（天地神龍ガイ・アスラ）** が弾の接頭辞なしで載っている。
BS10 でも同じ形（`X005R` 北斗七星龍ジーク・アポロドラゴン）があり、そのまま `X005R` で投入してある。
**BS11 も Wiki の表記どおり `X007` のままにする**（既存と揃える。ID を勝手に作らない）。

## 4. バッチ計画

**既存の器で書けるものを先に入れて、新機構は後段にまとめる**（BS10 と同じ進め方）。

| バッチ | 中身 | 前提 |
| --: | :-- | :-- |
| 1 | 既存の器で書ける分（おおよそ60枚強）。色ごとに分けて投入 | 無し |
| 2 | ブレイヴへの干渉（§1.2 の a〜g） | a は `pendingBraveKeeps` の流用、c は合体のタイミング制限の緩和 |
| 3 | リフレッシュステップの制限（§1.1） | リフレッシュステップの中断点を新設 |
| 4 | §1.3 の1枚もの | それぞれ個別 |

**枚数で進捗を数えない**（1枚に効果が2つも3つもある）。数えるなら効果節の単位で。
