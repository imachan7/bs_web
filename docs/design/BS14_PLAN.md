# BS14「覇王編 第1弾：英雄龍の伝説」実装計画

**121種**（`data/staging/BS14.json` は122件だが `SD06-007` は SD06 と重複するので取り込まない）。
バースト機構（[BURST.md](./BURST.md)）の上に乗る最初の弾で、**バーストに言及するカードが47枚**ある。

## 1. 確定した解釈（ユーザー確認済み。実装はこの通りに書く）

| 論点 | 結論 |
| :-- | :-- |
| BS14-093 リベレイションオーラの「**バーストがセットされている間**」 | **自分のバーストだけを見る**（2026-09-12 ユーザー確認）。「自分の」の省略。バーストエリアは非公開ゾーンで、他のカードはすべて自分側を見ているため。既存の `hasOwnBurstSet` をそのまま使う |
| BS14-041 / BS14-066 の「『ブロック時』効果は『アタック時』に発揮される」 | **既存の器を流用する**（新規不要）。BS01-149 アタックシフト／BS07-036 大械獣ギガ・テリウム／BS10-072 セイバーシャーク／BS09-077 アイスバーグ（【氷壁】のタイミング差し替え）と同型 |
| BS14-X01 の Lv4 | **対応済み**。BS10-X01 幻羅星龍ガイ・アスラに前例がある |
| BS14-055「自分の黄のマジックカード1枚を〜使用できる」 | ゾーンの明記が無いが**手札**と読む（この語法の既存カードと同じ） |

## 2. バースト機構に足りない軸（**確定スキーマ。勝手に変えない**）

BS14 のバースト条件は3種類だけで、うち1つが未対応:

| 条件 | 枚数 | 器 |
| :-- | :-- | :-- |
| 【バースト：自分のライフ減少後】 | 13 | 実装済み（`event:"ownLifeDamaged"`） |
| 【バースト：相手の『このスピリット/ブレイヴの召喚時』発揮後】 | 6 | 実装済み（`event:"opponentSummonEffectResolved"`） |
| 【バースト：相手による自分のスピリット破壊後】 | 9 | **`kind:"burst"` に `byOpponentEffectOnly?: true` を足す**（`event:"ownSpiritDestroyed"` + `subjectSide:"own"` と組み合わせる。判定は `eventInfo.byOpponentEffect`＝fieldEvent の同名軸と同じ） |

さらに3本足す:

- **`kind:"burst"` に `condition?`** — 「〜のとき、このスピリットカードを召喚する」の発動条件。
  既存の条件語彙を流用する（BS14-020＝トラッシュに紫のカード4枚以上／BS14-055＝トラッシュにマジック3枚以上／
  BS14-X01＝自分のライフ3以下／BS14-064＝自分のフィールドにネクサス3つ以上／BS14-X03＝フィールド/リザーブ/トラッシュのコア合計8個以上）。
  **条件を満たさないときは、そのアクションだけを飛ばす**（バースト自体は発動している）
- **`kind:"burst"` に `destroyedColorFilter?: Color`** — 「このバースト発動時に**紫の**スピリットが破壊されていたら」
  （BS14-X02／BS14-061）。破壊イベントの対象色は `fireOwnSpiritDestroyed` が既に `eventColors` で渡している
- **`kind:"burst"` の action から「そのとき破壊されたスピリット」を参照できるようにする**
  （BS14-103＝「このバースト発動時に破壊された、自分のトラッシュにあるスピリットカード1枚を手札に戻す」）

## 3. 新しいキーワード2つ

| キーワード | 実体 |
| :-- | :-- |
| 【呪滅撃】（BS14-X02 Lv3） | 「相手のライフのコア1個を相手のトラッシュに置くことで、このスピリットは回復状態でフィールドに残る」。**効果文に全文が書いてある**ので、`Keyword` に名前を登録し、効果は印刷どおり書く |
| 【大粉砕】 | **BS14 にこれを持つカードは無い。** BS14-062 が「【粉砕】/【大粉砕】を持つ自分のスピリットすべて」と**参照する側**にだけ出る。`Keyword` に名前を足すだけでよい |

## 4. バッチ分割

色ごとの6バッチ。**同じ `data/cards/BS14.json` を複数のエージェントが同時に書くと壊れる**ので、
各バッチは `data/staging/BS14-<色>.json` に**そのバッチぶんの配列だけ**を書き、メインループが結合して
`data/cards/BS14.json` を作る。

| バッチ | 枚数 | 重い札 |
| :-- | :-- | :-- |
| 赤 | 22 | BS14-X01（Lv4・バースト＋条件付き自己召喚）、BS14-011（シンボル追加） |
| 紫 | 20 | BS14-019（バースト効果のコア数+1）、BS14-X02（【呪滅撃】）、BS14-098（【不死】の先読み） |
| 緑 | 20 | BS14-032（【暴風】で疲労させた相手を記憶して手札へ）、BS14-X03（コア合計条件） |
| 白 | 20 | BS14-084（ライフ0回避＋トラッシュで効果を受けない）、BS14-X04（コスト合計ぶんバウンス） |
| 黄 | 20 | BS14-087（BPでなくLvを比べるバトル）、BS14-085（回復元の種別で破壊） |
| 青 | 20 | BS14-090（「合体時BP+」を0）、BS14-X06（相手の『破壊時』を封じる） |

## 5. 検証

バッチごとに `npm run typecheck && npm run validate:cards && npm run validate:notes && npm run validate:gaps && npm run smoke:quiet && npm run build:client`。
弾を入れ終わったら `npm run coverage:effects` と `npm run audit:choices` を回す。
