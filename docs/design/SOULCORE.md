- 初版: 2026-07-26 ／ **改訂: 2026-10-06**（コア統合 #165〜#169・pay（R5）・【転召】の分割を反映し、ユーザーの決定を取り込んだ）

- 出典: [バトスピ Wiki「ソウルコア」](https://batspi.com/index.php?%E3%82%BD%E3%82%A6%E3%83%AB%E3%82%B3%E3%82%A2)

## 0. 結論

1. **コアは数値のまま。ソウルコアは「どこにあるか」を指す1つの値で表す**（`PlayerState.soulCore`）。コア数を数えるだけの箇所は書き換えない
2. **烈火伝を取り込むまでは無効にする。** `soulCore` が未定義なら機構全体が素通りし、既存の対戦の挙動は1つも変わらない
3. ソウルコアが**行けないのはボイドとライフ**（創界神・創界石はゾーンが未実装）。コア統合のおかげで、出口は `removeCores` / `placeCores` / `removal.ts` の3つの共通関数と【転召】に集まっている
4. **いまのカード3枚はデータを変えずに正しくなる**（どれも「ソウルコア以外のコアをボイドへ」＝一般則そのもの）
5. 相手の効果でリザーブ/トラッシュへ動くときは、**毎回持ち主に聞く**（簡略化しない）
6. 支払いは**自動ならソウルコアを維持コアに回す**（コストは通常コアで払う）。手動支払いでソウルコアを選べるようにし、デメリットルールも一緒に入れる。**ここまで揃ってから有効化する**
7. 【転召】の対象は「上のコアすべてを指定先へ動かせるスピリット」に限る。**ソウルコアの乗ったスピリット（ボイド行き）と、コアを取り除けないスピリット（ガイ・アスラ）は対象にできない**。後者はソウルコアと無関係にいまのバグなので先に直す

## 1. ルール（出典から確定した事実）

- 各プレイヤーが1個だけ持つ。開始時は**通常コア3個＋ソウルコア1個**をリザーブに置く。2026-04-11 から使用は強制
- 基本は通常のコアと同じように使える
- **ライフ／ボイド／創界神／創界石には移動できない**（《封印》などソウルコアを対象とした効果を除く）
  - ライフ/ボイドへ置く効果では**可能な限り通常のコアを動かす**。通常のコアが無ければその分は不発
  - 複数のコアをまとめてボイドへ送る効果では、**ソウルコアだけがその場に残る**
  - マジックスパナ（BS05-083）は、ソウルコアの乗った造兵でも**通常コアを1個以上ボイドに置ければ**デッキ破棄まで解決する（造兵はソウルコアで残る）。【転召】と違い「すべて置けること」は条件にしない（2026-10-08 ユーザー確認）
- **相手の効果でコアがリザーブ/トラッシュへ動くとき、ソウルコアを含めるかは持ち主が選ぶ**（ライフ/ボイド行きでは含められない）
- **メインステップの 1:1 交換**: スピリット/アルティメット2体のあいだで、通常のコア1個とソウルコア1個を入れ替えられる。
  同時に動くので**コア1個のスピリットでも消滅しない**。夢魔の寝所（コア増加の検知）では**両方が疲労する**。
  コアを取り除けない効果が掛かっているときは交換できない
- **デメリットルール**: ソウルコアを動かす効果で**その効果を発揮したスピリット自身が消滅するなら、発揮そのものができない**（段7）
- 【ソウルドライブ】などで「除外」される（有効化の後）

## 2. 決定事項（2026-10-06 ユーザー確認）

| 論点 | 決定 |
| :-- | :-- |
| いつ有効にするか | **烈火伝の取り込みまで無効**。仕組みだけ入れ、対戦開始時の値1つで有効にする |
| 相手の効果でリザーブ/トラッシュへ動くとき（§1） | **毎回持ち主に聞く**（旧版の「含めない自動」案は撤回） |
| 支払い（自動） | **コストは通常コアで払い、召喚で置く維持コアにソウルコアを優先して回す**。通常コアだけでコストを払えないときは、自動ではソウルコアをコストに使わない（手動支払いへ） |
| 支払い（手動） | ソウルコアを支払い元に選べる。**有効化の前に入れる**。デメリットルール（§1）も同時に入れる |
| 【転召】の対象 | 上のコアすべてを指定先へ動かせるスピリットだけ。ボイド行きでソウルコアが乗っている／`coresCantBeRemoved` 系が掛かっているスピリットは対象外。候補から外れた理由を注意として出す |
| 破壊されたコアがボイドへ行く効果の下 | ソウルコアは**リザーブへ戻る** |
| 有効化までに入れるもの | 関所＋【転召】＋カード3枚、持ち主の選択、支払い（自動・手動）＋デメリットルール、1:1 交換、盤面の見た目 |
| 有効化の後でよいもの | 「ソウルコアで支払ったとき」誘発、「ソウルコアがある間」条件、《封印》、除外（烈火伝のカードを取り込むときに必要な分だけ） |

## 3. データモデル

```ts
export type SoulCoreLocation =
    | { zone: "reserve" }
    | { zone: "trash" }
    | { zone: "instance"; instanceId: string }   // スピリット/アルティメット/ネクサスの上
// PlayerState
soulCore?: SoulCoreLocation   // 未定義＝ソウルコア無効の対戦
```

- `zone: "life"`（《封印》）と `"removed"`（除外）は **いまは型に入れない**（使い道が来たときに足す）
- 有効化は対戦生成時のオプション1つ（`GameState.ts` の初期化で `reserve: INITIAL_RESERVE` の横に `soulCore: { zone: "reserve" }` を置くかどうか）。
  リザーブの数は 4 のまま（内訳が通常3＋ソウル1になるだけ）
- 公開情報なので `viewFor` で両者ぶんをそのまま配信する
- **置き場は新しいファイル `server/src/logic/zones/soulCore.ts`**（設計の2原則の2）。ここに置くのは次の3つだけ:
  - `movableNormalCores(state, pid, where)` … その場所から**通常コアとして**動かせる数（ソウルコアがあれば1引く）
  - `soulCoreFollow(state, pid, from, to)` … ソウルコアが動いたときにポインタを書き換える
  - `assertSoulCoreConsistent(state)` … 不変条件（ポインタの先に1個以上のコアがある・指すインスタンスが場にある）

### 3.1 なぜポインタか（旧版 §2.1 の要約）

識別が要るのはゲーム全体で2個だけ。`cores: number` を配列にするとコアを数えるだけの箇所すべてに配列操作が漏れる。
弱点（数値との二重管理・コンパイラが漏れを指摘しない）は、§6 段1の**出口の棚卸し**と、
段2の**有効化したAI自己対戦で毎手 `assertSoulCoreConsistent` を掛ける smoke** で塞ぐ。

## 4. 関所（ボイド/ライフへ通さない）

書き換えるのは次の共通関数だけ。**「実際に動いた数」を返す**形にそろえ、ボイド/ライフ行きは `movableNormalCores` を上限にする。

| 出口 | 場所 | 中身 |
| :-- | :-- | :-- |
| スピリット→ボイド | `removal.ts` `removeCoresToVoid` | 維持コア割れの判定は**実際に動いた数**で行う |
| removeCores の行き先 void | `actions/removeCores.ts` `depositTo` / `takeOneFromSource` / `applyToIndividual` | spread（ミイラバード）は**ソウルコアしか無い場所を候補から外す** |
| pay の可否 | `removeCoresAchievableCountForPay` | 通常コアだけで数える（天帝ホウオウガはリザーブがソウルコア1個だけなら払えない） |
| placeCores の取り元→ライフ/ボイド | `actions/placeCores.ts` `availableFromSource` / `takeFromSource` | 行き先がライフ/ボイドのときだけ通常コアに限る |
| 破壊されたコアの行き先がボイド | `removal.ts:493`（`redirect === "void"`） | ソウルコアは**通常の行き先（リザーブ）**へ |
| 【転召】 | `keywords/tensho.ts` `tenshoCandidates` | dest:void ではソウルコアの乗ったスピリットを**候補から外す**（コアが残って生き残る状況はそもそも作らない）。外したときは理由を注意で出す |

**ボイド/ライフ以外の出口（ポインタが追従すべき移動）は段1の調査で全部挙げる。**
主なもの: スピリットが場を離れる（破壊・手札/デッキへ戻る・転召）、リフレッシュステップのトラッシュ→リザーブ、
手動のコア移動（`moveCore`）、ブレイヴの分離。ここで漏れると不変条件が破れる。

## 5. 持ち主の選択（§1 の「含めるか」）

- 発生するのは: 行き先が**リザーブ/トラッシュ**で、取られる個体に**ソウルコアが乗っていて**、取る数がその個体のコア数**未満**のとき
  （全部取るなら必ず含む・通常コアが足りないなら必ず含む＝聞かない）
- 選ぶのは**その個体の持ち主**（相手の効果でも自分の効果でも持ち主）。`PendingChoice` に yes/no を1種足す
- 中断の書き方は [INTERRUPTION_POINTS.md](./INTERRUPTION_POINTS.md) に従う。範囲効果（全スピリットから1個ずつ等）は**ソウルコアの乗った1体だけ**が聞かれる
- AI は常に「含めない」
- 置き場: 判定と選択肢の生成は `zones/soulCore.ts`、中断点は `removal.ts` の `removeCores` / `removeCoresToTrash`（全経路が通る）
