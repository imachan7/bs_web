# アタックステップのタイミング表（2026-08-14 ユーザー提供）

**バトル中の「いつ何が起きるか」の一次資料**。効果の解決順で迷ったらまずここを見る。
接続詞（「その後」「さらに」等）は [CONJUNCTION.md](./CONJUNCTION.md)、
中断された側の書き方は [RESUME_STACK.md](./RESUME_STACK.md)。

## 0. 同時発揮の一般則（バトル以外にも効く）

2つ以上の効果が同じタイミングで同時に発揮することがある。そのときは:

1. まず **A：ゲーム中・ターン中・ステップの間、ずっと発揮し続ける効果**（継続効果）を解決する
2. 次に **B：決められたタイミングや条件で発揮する効果**を解決する
3. **A と B のそれぞれの中で複数が同時に発揮する場合は、ターンプレイヤーが解決順を決める**
4. 先に解決した効果によって新しい効果が発揮したときは、**新しく発揮した効果を先に解決する**

## 1. タイミング表

```
＞０：アタックステップ開始時タイミング
　　　アタックステップの開始を宣言
　　　「アタックステップ開始時」と指示された効果を発揮
　　　攻撃強制・攻撃規制等

＞１：アタック宣言タイミング
　　　１：アタッカーを疲労させてアタックを宣言
　　　２：即効性アタック時効果：「強襲・粉砕等」
　　　３：アタック後バースト

＞２：ブロック宣言前フラッシュタイミング
　　　１：ブロック側フラッシュ使用
　　　２：アタック側フラッシュ使用
　　　３：ブロック側フラッシュパス
　　　４：アタック側フラッシュ使用
　　　５：ブロック側フラッシュパス
　　　６：アタック側フラッシュパス
　　　※互いが連続的にパスした時点で終了

＞３：ブロック宣言タイミング
　　　１Ｂ：ブロッカーを疲労してブロック宣言・遅効性アタック時Ｂ発揮：激突
　　　２Ｂ：ブロック時効果発揮
　　　　　　「４」へ進む
　　　１Ｌ：「ライフで受ける」宣言
　　　　　　ブロックしない場合、「４」はパスして「５」へ進む

＞４：ブロック宣言後フラッシュタイミング（＞２と同じ手順）

＞５：バトル解決時タイミング
　　　１Ｂ：アタッカーとブロッカーのＢＰを比較して破壊確定

　　　２Ｌ：ライフ減少後バースト発揮

＞６：破壊処理タイミング
　　　１：破壊時効果発揮・破壊されたとき効果発揮
　　　２：破壊後バースト発揮

＞７：バトル終了宣言タイミング
　　　１：アタック中のみの効果が消失
　　　２：バトル終了時効果発揮・遅効性アタック時Ｅ発揮：光芒・呪撃
```

## 1.5 ＞６「破壊処理」と**破壊待機状態**（2026-08-14 ユーザー確認）

＞６は1手ではない。**破壊されたカードはすぐには場を離れない**:

```
1. スピリット／アルティメット／ネクサスは破壊されると「破壊待機状態」になる
   （＝まだフィールドにいる）

2. 『このスピリットの破壊時』「〜が破壊されたとき」等、破壊時に誘発した効果があれば発揮する
   ※ このとき、**破壊されたスピリットのシンボルも軽減シンボルに数えられる**
   ※ 派生効果の解決軸・同時発揮の順番は §0 の一般則に従う

3. 破壊待機状態のカードすべてをトラッシュに置く
   ※ その前に、破壊待機状態の合体スピリット／合体アルティメットの
     **ブレイヴを残すかどうか**を選ぶ

4. その後、乗っていたコアをすべてリザーブへ移動させる
   ※ ブレイヴを残すことを選んだ場合は、スピリット状態になったブレイヴに、
     リザーブ／フィールドにあるコアを好きなだけ維持コストとして置く
```

### 破壊待機状態の性質

**定義**: BP比べ、または何らかの効果によってフィールドに存在するカードが破壊されている状態。

| 性質 | 内容 |
| :-- | :-- |
| 場所 | **まだフィールドに存在する** |
| コア | **カードがトラッシュに置かれるまで乗ったまま** |
| 効果の対象 | **カードの効果の影響を受ける**（対象に取れる） |
| 自分の効果 | **誘発も継続効果も、普通に全部働く**（2026-08-14 ユーザー確認） |
| 疲労・回復 | **できない** |
| さらなる破壊 | 基本的に**待機状態からさらに破壊されることはない** |
| 解除されたとき | 「〜破壊されたとき、〜することで、自分のフィールドに残る／戻る」等で破壊待機状態でなくなったカードは、**破壊される前と同じ状態**でフィールドにとどまる |

### ⚠️ 効果テキストの「戻る」は**トラッシュからではない**

「疲労状態で自分のフィールドに**戻る**」の「戻る」は、**破壊待機状態から（通常の状態へ）戻る**という意味で、
トラッシュから場に出し直すことではない。**後の弾でこの記述は「残る」に変更された**（同じ意味）。

実装は当初からこの解釈で書けている（`kind:"reviveOnDestroy"` は場に留める処理で、
トラッシュからの回収ではない）。BS01〜08 の該当14枚すべてが `reviveOnDestroy` になっていることを
2026-08-14 に実データで確認済み。**新しい弾を取り込むときも「戻る」を回収と読まないこと。**

### ⚠️ 【転召】との相互作用

破壊で誘発した効果が**スピリットを召喚する**とき（例：【不死】）、
その召喚するカードが【転召】を持っていた場合、
**破壊待機状態のスピリットを【転召】の対象（生贄）にできる**。

破壊待機状態のカードはまだフィールドにいるため。手順としては
「破壊待機のスピリットのコアをすべて置く → そのスピリットは破壊待機のままトラッシュへ」となる。

### 実装状況（2026-08-14 時点）

**破壊待機状態は導入済み**。スピリット（`destroySpirit`）もネクサス（`destroyNexus`）も
「**破壊待機にする → 破壊時の誘発を解決 → カードをトラッシュへ → コアをリザーブへ**」の順で動く
（印は `CardInstance.pendingDestruction`）。誘発が選択待ちで中断しても、`ResumeFrame` の
`destroyCommit` / `destroyNexusCommit` が**待機状態のまま**残りを引き継ぐ。

| 項目 | 状態 |
| :-- | :-- |
| 誘発の解決中も場にいる（数・シンボル・効果の対象） | **対応済み** |
| コアが乗ったまま | **対応済み** |
| 待機中も誘発・継続効果が働く | **対応済み**（場にいるので走査にそのまま入る） |
| 疲労・回復できない | **対応済み**（`exhaustSpirit` / `refreshSpirit` が弾く） |
| そこからさらに破壊されない | **対応済み**（スピリット・ネクサスとも。維持コア割れも同じ） |
| 「フィールドに残る／戻る」＝待機状態の解除 | **対応済み**（スピリットは `applyRevived`、ネクサスは `reviveLastDestroyedNexus`） |
| 【転召】の生贄にできる | **対応済み**（`tenshoCandidates` は場のスピリットをそのまま見る） |
| 合体スピリットのブレイヴを残す選択 | **未対応**（ブレイヴ自体が未実装） |
| アタック・ブロックの可否 | 未対応。破壊待機中にアタック宣言は起きないので実害なし |

**この変更で挙動が変わったカード**（テストで固定済み）:

- 宝石の獣カーバルク：『破壊時』「自分のフィールドにいる系統：「想獣」1体につき」に
  **破壊された自分自身が数に入る**ようになった
- 兵隊アントマン：『破壊時』の召喚で、**自分のコアはまだ戻らず**（＝使えない）、
  一方で**自分のシンボルは軽減に数えられる**
- 盾精ラングリーズ／神鳴る霊峰：破壊されたスピリットのコアを、リザーブ経由ではなく
  **待機中の本体から直接**移すようになった
- 「破壊時に手札に戻る」（returnSelfToHand）：トラッシュからではなく
  **破壊待機状態から**手札へ移すようになった
- 戦闘獣ジャッカー：「その破壊されたネクサスを自分のフィールドに戻す」は、
  トラッシュからの再配置ではなく**破壊待機状態の解除**になった
  （＝**コアもレベルもそのまま**残る。以前は Lv1・コア0 で置き直していた）

## 1.6 **バウンス待機状態**（2026-08-16。一次資料＝バトスピ Wiki「バウンスについて」）

手札／デッキへ戻す効果（バウンス）にも待機状態がある（2020年5月のルール改定）。手順は:

1. 「手札／デッキに戻す」効果を発揮・解決する
2. 対象は「**バウンス待機状態**」となり、**フィールドに留まる**
3. 待機中に発揮できるのは「フィールドを離れるとき」「手札／デッキに戻るとき」の効果**だけ**
4. フィールドに残す効果がなければ、指定の場所（手札／デッキ上／デッキ下）へ移る

### 破壊待機状態との違い（**混同しないこと**）

| | 破壊待機（§1.5） | **バウンス待機** |
| :-- | :-- | :-- |
| シンボルを軽減に使える | ○ | **×** |
| 戻る／破壊に**無関係な効果の対象**になる | ○（数・シンボル・【転召】の生贄にも数える） | **×** |
| 発揮できる効果 | 破壊時・フィールドを離れるとき | 戻るとき・フィールドを離れるとき |

### ここから出る実装上の規則

- **1つの効果で複数体を戻すときは、全部を待機させてから一度に戻す**。
  1体ずつ戻すと、1体目の「戻ったとき」の誘発が2体目以降の対象を変えてしまう
  （実際に「コスト1以下すべてを手札に戻す」×「地竜が手札に戻ったとき相手1体を破壊」の
  組み合わせで、戻るはずだった相手が破壊されていた。smoke part194 で固定）
- 1体だけ戻す場合は待機させてすぐ戻して構わない（結果が変わらないため）
- 実装は `CardInstance.pendingBounce`。`markBounce` で待機させ、効果の解決が終わった時点で
  `flushBounces` が移動と誘発をまとめて行う（誘発が選択待ちで中断したら `bounceFlush` フレームへ）

## 1.7 **ブロックの強制は「効果」なので、装甲などで防げる**（2026-08-16。一次資料＝Wiki「激突」）

【激突】は「相手のスピリットすべては、可能ならブロックする」という**相手のスピリットを対象とした効果**。
したがって:

- **装甲で無効化できる**。相手にアタッカーの色に対する装甲を持つスピリットしかいなければ、
  ブロック強制を無視して**ライフで受けられる**
- 「相手の効果を受けない」耐性があれば当然ブロック強制も適用されない
- 「可能なら」なのでブロックできる個体がいなければ強制されない（既存どおり）

**同じ理屈で、効果によるブロック強制（`mustBlockGrant`。燃えさかる戦場／翼持つ者の空域／
ワーニングアタック）も装甲で防げる**（2026-08-16 ユーザー判断で揃えた）。

実装は `RuleValidator.hasLegalBlocker` に**強制の発生源**を渡し、`boardResistanceAgainst` で
「その効果を受けない個体」を数から外す。渡さなければ従来どおり（ブロック可否だけ）。
**それまでブロック可否しか見ておらず、装甲を素通りしていた**（ユーザー指摘で発覚。smoke part195）。

## 2. ここから確定した実装上の規則（2026-08-14 ユーザー確認）

- **BP比較（＞５）は破壊処理（＞６）より先**。したがって
  『BPを比べ相手のスピリットだけを破壊したとき』（`kind:"battleWon"` 35枚・`onBattleLose` 1枚）は、
  **敗者が「フィールドに残る」で生き残っても発揮する**。復活は＞６の話なので勝敗の判定を覆さない
  （→ 効果の実装は現状のままでよい）
- **【呪撃】・【光芒】は＞７**。＞６で「フィールドに残る」を使って生き残った個体は、
  ＞７の時点でまだフィールドにいる＝**【呪撃】の対象になる**
- **相打ち（同BP）は＞６の同時破壊**。「フィールドに残る」と「破壊されたとき」は同じステップなので、
  §0-3 により **ターンプレイヤーが「どちらのスピリットから破壊処理をするか」を選ぶ**。
  粒度は**体ごと**（選んだ側の「残る」→「破壊されたとき」を最後まで解決してから、もう片方へ）
- 上の「ターンプレイヤーが順番を決める」は**バトルに限らない**。`destroyAll` のような同時破壊でも、
  「フィールドに残る」の確認が**2体以上**に出るなら、その都度ターンプレイヤーに順番を聞く
  （1体しか出ないなら聞かない）
- **順番が結果を変える実例：【不死】（BS09）**（2026-08-14 ユーザー確認）。
  【不死】は「トラッシュにあるこのカードは、自分のコストNのスピリットが破壊されたとき召喚できる」で、
  同じ破壊に対して「フィールドに残る」と**同時に発揮する**。したがって:
  - **「フィールドに残る」を先に解決すると、その個体は破壊されなかったことになり【不死】は発動できない**
  - **【不死】を先に解決できれば発動できる**

  つまりターンプレイヤーの順番の決定が、そのまま【不死】が撃てるかを決める。
  **順番を聞く候補は「復活の確認」だけでなく、その破壊で同時に発揮する効果すべて**である
  （実装は `wouldAskReviveConfirm` の下見を、同時発揮する効果すべてを数える形へ広げること）

## 3. 「フィールドに残る」と「破壊したとき」の関係（接続詞で変わる）

[RESUME_STACK.md §7](./RESUME_STACK.md) に既出。要約:

- **① 別効果の「破壊したとき〜する」**: 復活で**阻止できる**（復活した個体は破壊されていない）
- **② 「破壊することで」「破壊し、そうしたとき」**: 同時発揮なので**阻止できない**

**①②はどちらも「効果による破壊」の話で、＞５のBP比較による勝敗判定とは別**。
BP比較の結果に紐づく『BPを比べ相手のスピリットだけを破壊したとき』は §2 のとおり阻止できない。
