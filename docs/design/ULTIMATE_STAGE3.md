## 判断が要るとされた行の決着（効果文で決まる。ユーザーへの質問は不要）

規則は ULTIMATE_PLAN B1（「スピリット」と書いた効果はアルティメットに当たらない）・B2（「フィールド」は当たる）。**印刷が「スピリット/ネクサス」ならアルティメットを含めず、「フィールド」なら含める。**

- `ownColorTotalAtLeast`（ポム・ペンタン・道化師クラン：「黄のスピリット/ネクサスが合計3つ以上」）・`hasOwnColor`（リブ・リーパー：「赤のスピリット/ネクサスが自分のフィールドにある間」）・`ownAllHaveTeam`（「自分のスピリット/ネクサスすべて」）・`fieldColorCount(spiritsOnly)`・`ownCombinedBraves`（「合体スピリットのブレイヴ」。B13）→ スピリットのまま。
- `ownFieldSymbolColors`（俊星流れるコロッセオ・力奪う凱旋門：「フィールドにあるシンボル」）→ アルティメットを含める。極は段1 の `onlyColors` で色から除かれる（B11）。
- `removeCores` の置き場の指定で spirit と nexus を両方含む 26 件：効果文が「フィールド」（「フィールド/リザーブ」「フィールド上」を含む）の 21 件はアルティメットを含める。「スピリット/ネクサスのコア」（BS17-012）・「スピリット/ネクサスのコア4個」（BS04-096）・「スピリット1体かネクサス1つ」（BS02-022）の 5 件は含めない。**「spirit と nexus が並べばフィールド」という推定は外れる**ので、データに置き場 `"field"`（スピリット・アルティメット・ネクサス）を足して 21 件をそれへ移す（名前で意味が分かる形。設計の原則3）。
- placeCores.ts:163・303：分岐ごとに分類する（`anyField` だけコア）。moveCards.ts:549（合体先ホストの列挙）：スピリットのまま（B13 は braveCombineCandidates 側）。

## ヘルパー（呼び出し元ごとの仕分けを減らす）

`findSpirit`（約80か所。自分の側だけ）は**広げない**。`findSpiritAny`（両陣営。約84か所）は 3a で `battlers` から引く形に広げた：id で引くだけなので、スピリットの候補から選んだ id はこれまでどおり見つかり、アルティメットの id を渡さない限り結果は変わらない（アルティメットを選べるのは段5 の `kinds` から）。新しい名前で受ける：
`findBattler(player, id)`・`isOnField(player, inst)`（既存 `isOnFieldAnyZone` に1行足す）・`leaveField`（splice＋下のカード・ソウルコア・合体の解除の手順が7か所に書き写されている）・`hostsOf`（合体先ホスト）・`ownerPidOfInstance`（持ち主の逆引き）。
