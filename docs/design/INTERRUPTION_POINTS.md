# 効果解決の中断点（プレイヤーに選ばせる場所）の設計

2026-08-10 起票。「効果の要所要所に中断点がないとコードにしづらい効果が増えてくる」という
指摘を受けて、**現状の骨格・層ごとの可否・使い分け**を1枚にまとめたもの。

新しい効果で「ここでプレイヤーに選ばせたい」となったとき、
**まずこの表を見て、どのパターンで書けるかを決める**。当てはまらないなら中断点の新設を検討する。

## 1. 現状の骨格（すでにあるもの）

中断・再開そのものは動いている。`pendingChoice` に「選択待ち」と**再開に必要なもの**を積み、
応答（`GameAction "resolveChoice"`）が来たら保存した action を解決し直す。

| 仕組み | 役割 |
| :-- | :-- |
| `PendingChoice.action` / `selfInstanceId` | 中断した1件の再開情報。選択後に `resolveAction` へ渡し直す |
| `PendingChoice.queue` | 同一トリガー内の**残りエントリ**の退避（`fireTrigger` / `resolveMagic` のループが積む） |
| `PendingChoice.actorPid` | **選択者と実行者を分ける**。「相手に選ばせるが、効果は発生源の持ち主のものとして解決する」（【暴風】の `chooserIsTarget`／BS08ダークスカルデーモン） |
| `PendingChoice.resolveOnSkip` | **スキップされたときも action を解決し直す**。「選び終わってから後処理がある」効果用（後述のパターンB） |
| `GameState.turnStartResumeStep` | ステップ誘発の選択で中断した**ターン開始処理**を、途中のステップから再開する |
| `state.interactiveTargets` | 対戦では true、テストでは false。**false のときは選択を出さず決定的に自動選択する**（既存テストを壊さないための逃げ道） |

選択の発行口は `requestChoice`（対象・選択肢）と `requestCardChoice`（手札・トラッシュ・公開ゾーン）の2つで、
アクションハンドラから **41箇所**（2026-08-10 時点）呼ばれている。

## 2. 層ごとの可否（ここが本題）

**中断できるかどうかは「どの層にいるか」で決まる。**

| 層 | 中断 | 理由 |
| :-- | :-- | :-- |
| `shared/rules.ts` の述語（装甲・実効BP・コスト計算） | **✕** | クライアントも同じ実装を呼ぶ。値を返すのが契約で、そこに選択は持ち込めない |
| サーバーの同期判定（`resistanceAgainst` / `bothSidesPids`） | **✕** | 呼び出し元がその場で値を必要とする |
| アクションハンドラ（`server/src/logic/actions/*`） | **○** | `requestChoice` → action 保存 → 再入。**基本はここで聞く** |
| 誘発／マジックのエントリループ | **○** | 残りを `queue` に積んで中断できる |
| ターン開始処理（`PhaseManager`） | **○** | `turnStartResumeStep` で途中から再開 |
| `handleAction` の入口（`GameEngine.dispatchAction`） | **○** | そもそも解決の外側。設定操作はここで受ける |

## 3. 3つのパターンと使い分け

### パターンA：アクションハンドラで聞く（既定。まずこれを検討する）

```ts
if (targetInstanceId === undefined && state.interactiveTargets && candidates.length >= 2) {
    requestChoice(state, owner, "…を選んでください", candidates.map((s) => s.instanceId), false, action, self)
    return
}
```

- **候補2体以上のときだけ聞く**（1体なら即確定、0体なら不発）
- 非対話モードでは従来どおり自動選択を残す
- 応答は既存の `{ type: "resolveChoice", instanceId }`。**UI側の追加実装は不要**

例：BS04強者統べる大地Lv2（ブロックされないスピリットの指定）

### パターンB：途中経過を action に載せて再入する（複数回の選択にまたがる効果）

「好きなだけ〜する」のように選択が繰り返される効果。**内部フィールドを action に持たせて持ち回る**
（`cards.json` には書かない）。

```ts
// 破棄のたびに ctx.resolve({ ...rest, discardedSoFar: n + 1 }) で再入し、
// スキップで戻ってきたとき（resolveOnSkip）にまとめてドローする
```

- **後処理を伴うなら `resolveOnSkip` を立てる**。これが無いとスキップ＝即終了になり、後処理が書けない
- ⚠️ **1回ごとに結果を確定させない**。BS08堕天使ミカファール／BS02マジックブックは
  「1枚破棄→即1枚ドロー→また尋ねる」と書いていたため、**引いたカードをまた破棄できて無限に回せた**。
  「全部選ばせる → まとめて適用」の順にすること

例：BS08堕天使ミカファール、BS02マジックブック

#### B′：盤面を押して選ぶなら**トグル**にする（2026-08-24 ユーザー確定）

パターンBのうち、**フィールドのスピリットをクリックして選ぶ**もの
（`destroyByCostBudget` / `destroyByBpBudget` の「予算内で好きなだけ破壊する」）は、
1体ずつ聞き直すだけだと「間違えて選んだものを取り消せない」「あと何を選んだか分からない」。

- **選択済みも候補（`candidates`）に残す** → もう一度押すと選択が外れる
- `PendingChoice.selectedIds` に選択済みを入れる → クライアントが緑枠で描く（`.choice-selected`）
- **合計は `prompt` に出す**（「コスト合計 4／5」）。予算に収まらない未選択は候補から外す
- `PendingChoice.skipLabel` でスキップボタンを「これで破壊する（2体）」に差し替える
  （このパターンではスキップが**中止ではなく確定**を意味するため）。`resolveOnSkip` とセット

⚠️ **自動応答（smoke の対話モード・part190 の火入れ）は `candidates[0]` を押し続けるので、
そのままだと選択と解除を往復して終わらない。** 共通の `autoPickTarget`（`scripts/smoke/helpers.ts`）
が「まだ選んでいないものを足し、無くなったらスキップ」を行う。新しいトグル選択を足すときは
必ずこれを経由させること。

### パターンC：意思をあらかじめ盤面の状態にする（述語層から中断できないとき）

述語層（装甲など）で「プレイヤーの意思」が必要になったら、**その場で聞くのを諦めて、
先に盤面の状態にしておく**。判定側は装甲とまったく同じ同期の述語のままでよい。

```ts
// 判定側（装甲の判定の隣に1行）
if (player.payToNegate === false) return null
// 切り替えは handleAction の入口で受ける（降参と同じく手順の外側の操作）
```

- **既定値は従来の挙動に合わせる**（未設定 = true）。設定しなければ何も変わらない状態にしておく
- UIにはトグルが要る。現在値は自分側のビューにだけ返す
- 引き換えに「効果ごとに個別判断できない」ので、**ズレは `card-notes.json` に書く**

例：BS08竜騎集う円卓Lv2（手札を破棄して効果を受けない）→ **2026-08-17 にパターンDへ移した**

### パターンD：述語の**手前**で聞いて、答えを盤面に置いてから判定へ入る（2026-08-17）

パターンCの改良。「装甲と同じ同期の述語なので聞けない」は**述語の中の話**で、
**その述語を呼ぶ直前**はアクションハンドラの層なので中断できる。
そこで「対象が確定してから適用するまで」の間に聞き、答えを state に置いてから判定へ入る。

```ts
// 呼び出し元（resistanceAgainst の直前）
if (askPayToNegateIfNeeded(state, found.pid, found.inst, attempt, action, self, sourceName)) return
const resisted = resistanceAgainst(state, found.pid, found.inst, attempt)
```

- 聞くときの action は**確認専用のアクション**にして、元のアクションを `resume` に抱かせる
  （`payNegateDecide`。`cards.json` には書かない。`INTERNAL_ONLY_ACTIONS` に登録する）
- **`ctx.resolve` は `targetInstanceId` を暗黙に引き継がない。**
  `resume` を解決するとき明示的に渡すこと（渡さないと「対象指定なし」の経路に落ちて別の個体を巻き込む）
- 選択者と実行者が違うので `chooserPid` を使う。
  **`pid` に実行者、`chooserPid` に選ぶ側**を渡す（両方同じ値にすると `actorPid` が立たず、
  再開時に効果が守る側のものとして解決されてしまう）
- 答えは**1回の対象化につき1つ**。判定側は**読んだら消費する**（`delete state.payNegateDecision`）
- パターンCと違い**効果ごとに判断できる**ので、`card-notes.json` のズレが消える

例：BS08竜騎集う円卓Lv2（相手のスピリットの効果の対象になるたび、手札1枚を破棄して受けない）

### 選択を「やめられる」ようにするとき（2026-08-21 ユーザー確定）

**起動能力（`kind:"activated"`）から出した選択をやめたら、「そもそも効果を発揮しなかった」扱いにする。**
「ターンに1回」（`oncePerTurn`）も消費せず、同じターンにもう一度起動できる。
起動ボタンを押してから対象を見て「やっぱりやめる」ができないと、対象を確かめる手段が無いため。

**適用範囲は `timing:"main"` の起動能力だけ**（＝BS08帝竜騎サイクル6枚。追加コストが無いので巻き戻しが要らない）。
バトル中のコア払い・疲労を伴う起動能力は**現状のまま**（やめてもコストは戻らない）。

実装の道筋（3点セット）:

1. アクションに `cancelable` を書く（いまは `summonFromHandFree` のみ）。ハンドラは
   **候補が1枚でも必ず聞き**（`alwaysAsk`）、`optional: true` で出す
2. `doActivateAbility` が解決後に `PendingChoice.revertActivated = { instanceId, effectId }` を載せ、
   `doResolveChoice` が**選ばなかったとき**に消費を巻き戻す
3. 候補が0枚でその場で終わった場合は、ハンドラが `GameState.activationFizzled` を立て、
   `doActivateAbility` が同じく巻き戻す（起動しても何も起きないなら消費しない）

## 4. まだ中断点が無く、今後困りそうなところ

| 場所 | 何が書けないか | 今の回避策 |
| :-- | :-- | :-- |
| `bothSidesPids()` | 「効果の対象を相手のみ／自分のみに変更できる」の選択（BS02封印された魔導書Lv1） | 自動判定（不利益なら自分を外す）。**マジック使用の入口で1回聞いて state に置く**のが有力 |
| `shared/cost.ts` のコスト計算 | 「コストを支払わずに使用**できる**」の可否選択（BS07大天使イスフィール） | 常に無償化。**`castMagic` の入口で聞く**のが有力 |
| ~~効果の適用直前（対象ごと）~~ | ~~「対象になる**たび**」に払うかを個別に決める~~ | **解決済み（2026-08-17）→ 下のパターンD** |
| 同時に誘発した複数の効果 | 解決順をプレイヤーが選ぶ | 定義順に解決（現状ズレの報告は無い） |

## 5. 新しい中断点を足すときの手順

1. **まず層を確認する**（§2）。アクションハンドラ以上なら、たいていパターンAかBで足りる
2. 述語層から離れられないなら**パターンC**を検討する。既定値を従来の挙動に合わせること
3. `interactiveTargets === false`（テスト）では**必ず従来どおり自動で進む**ようにする。
   ここを忘れると既存の smoke が大量に落ちる
4. 選択の形（`kind`）が既存の `target` / `option` / `card` で足りるかを見る。
   **足りないなら UI側の実装が要る**ので、着手前に chatbox で形を合意する
5. テストは**対話・非対話の両経路**と、候補0/1件の分岐まで書く
