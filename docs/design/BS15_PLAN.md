### 2.4 Q&A で見つかった一般則（BS15 以外にも効く。⚠️ 実装を確認すること）

- **「破壊されたとき」は、一度に2体以上破壊されても1回と数える**（Q22359：063 吊られた古城 Lv2 で残せるのは1体だけ）。
  ⚠️ **現行エンジンは食い違っている**：`fireOwnSpiritDestroyed`（removal.ts）は**破壊された1体ごと**に
  `ownSpiritDestroyed` を発火している。BS15 だけでなく既存の「自分のスピリットが破壊されたとき」全般に効くので、
  **BS15 とは別の作業としてユーザー確認のうえ直す**（効果文に「破壊されたスピリット1体につき」と書いてある札は別扱い）
- 「〜している間」の条件は**ステップの途中でも満たさなくなった瞬間に**効果が切れる（Q20166：060 バンディット・アームズ）
- コアが0個になって破壊されたスピリットは Lv0 なので、「Lv◯のスピリットが破壊されたとき」は発揮しない（Q22358）
- X05 カグヤ「Lv1〜Lv4 BP を 2000 として扱う」は**レベルごとのBPを書き換える**効果。あとから BP+ すれば加算される。
  合体スピリットは**ブレイヴの BP+ を含めて** 2000（Q3629〜Q3632）

## 5. 検証（メインループが統合後に1回）

```
npm run typecheck && npm run validate:cards && npm run validate:notes && npm run validate:gaps && npm run smoke:quiet && npm run build:client
```

弾を入れ終わったら、定型に**入れていない**次も回す:

| コマンド | 見るもの |
| :-- | :-- |
| `npm run coverage:effects` | 書いたのに一度も発火していない効果 |
| `npm run audit:choices` | 対戦者が選ぶべき場面を実装が決めていないか |
| `npm run audit:semantics` | テキストと実装の解釈違い（**S6 は精度が高い**。S7 は疑い止まり） |
| `npm run audit:parity` | クライアントが出すボタンをサーバーが拒否しないか |

`npm run gaps:update` でベースラインを縮める。意図的に実装しない札は `data/card-notes.json` に理由を書く。

## 6. 出し方

**PR は1つの作業単位で出す**（2026-09-13 ユーザー指示）。BS15 は「弾の取り込み」という
同種の作業なので**弾ごと1つの PR でよい**。ただし次は分ける:

- 取り込みの過程で見つかった**既存カードのバグ修正**
- **監査ツール・smoke の仕組み**の改良
- **インフラ・ドキュメント**

`main` へマージすると **GitHub Actions が自動で Cloud Run へデプロイする**
（2026-09-13 に設定。[DEPLOY_CLOUDRUN.md](../ops/DEPLOY_CLOUDRUN.md)）。
手で `gcloud run deploy` を打つ必要はない。**マージ＝本番反映**である点に注意。

弾が入り終わったら `data/announcements.json` に1行足す（対戦者が読む文面。内部用語を書かない）。
