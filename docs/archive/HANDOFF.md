### 直交化で変わったこと（カードを追加する人向け・重要）

**新しい絞り込み軸が必要でも、アクションに個別フィールドを足さないこと。**
`server/src/type.ts` の `TargetFilter` に1つ足せば、`filter` を受け取る全アクションが扱える。
判定は `shared/rules.ts` の `matchesTarget()` 1箇所。旧形式（`maxBp` 直書き等）も動くが、
**新規データは `filter` 形式で書く**。

```jsonc
{ "type": "destroy", "count": 1, "filter": { "maxBp": 5000, "color": "red", "cost": { "max": 3 } } }
```

## 4. インフラ・運用（直近で整備済み）

### CI/CD が機能するようになった

`main` への push で **typecheck → smoke → E2E → デプロイ → デプロイ後ヘルスチェック** が自動実行される
（`.github/workflows/azure-deploy.yml`）。PR #4 で初回成功を確認済み。

- **開発は `gamestate`、リリースは `main` へマージ**という運用
- 検証が1つでも落ちればデプロイされない
- **デプロイ後ヘルスチェック**は、ビルドもテストも通るのに本番だけ起動しない事故を検知するために追加した
  （実際に `shared/` の同梱漏れで起こりうる状態だった）

### 手動デプロイ（Actions が使えないときの退避路）

DEPLOY.md 5.5 に手順あり。**要点は2つ**:

- **`shared/` を必ず zip に含める**（リファクタで `server/src` が実行時に `shared/*` を import するようになった。
  含め忘れると本番が `MODULE_NOT_FOUND` で起動しない）
- **zip は毎回削除してから作る**（同名の古い zip が残っていて「デプロイしたのに反映されない」事故が実際に発生した）
